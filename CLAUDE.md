# Правила работы над True Thrills

Файл для Claude Code. Короткий и обязательный к исполнению.

## Спрашивать до правки, а не отчитываться после

Если при переносе чужого пакета, правке экрана или чистке кода возникает
вопрос **что оставить, а что заменить** — спросить владельца до изменения.
Не решать за него и не ставить перед фактом.

Спрашивать обязательно, когда:

- чужой пакет возвращает то, что владелец раньше просил убрать;
- из экрана исчезает то, что он видел и чем пользовался (блок, кнопка, список);
- правило, которое он сам установил, перестаёт выполняться;
- выбор между двумя видами и оба выглядят разумно.

Не спрашивать и делать молча:

- исправление явной поломки;
- то, что он уже назвал словами в этом разговоре;
- внутреннее устройство кода, которое на экране не видно.

Вопрос задавать до работы, а не после: переделывать дороже, чем уточнить.

## Проверки

Проверка, которая ничего не находит, — это не проверка. Новые проверки
прогонять мутацией: сломать код, убедиться, что прогон называет поломку
словами, вернуть обратно. Для логики и для самих проверок — обязательно,
для косметики — нет.

Селекторы проверок сверяются с исходниками (`tests/selectors-alive.mjs`):
переименовал класс — почини проверку, а не оставляй её слепой.

## Телефон и студия

`tests/fixtures/layout-lock.json` держит координаты опорных элементов
главной, каталога, эфира и студии. Работа над сайтом для ПК не должна их
двигать. Меняешь телефон намеренно — пересними замок и скажи об этом в
сообщении коммита:

```
TT_LOCK_WRITE=1 npm run test:design
```

## Чего не делать никогда

- Не выкладывать ключ SSH, `.env` сервера, `firebase-service-account.json`
  и ключ подписи APK — ни в архив, ни в переписку.
- Не включать сообщество без заполненных «ответственного за данные» и
  адреса для связи: это решение владельца, а не настройка.
- Не выдавать непроверенное за проверенное. Не прогнал — так и сказать.
