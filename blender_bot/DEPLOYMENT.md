# Полная инструкция: от идеи до автономного Telegram-бота

Пошаговое руководство: как создать Telegram-бота и разместить его на бесплатном
сервере так, чтобы он работал 24/7 сам по себе, независимо от вашего компьютера.
Инструкция написана по следам реального прохождения всего пути — включая все
ошибки, на которые мы наступили, и как их обойти сразу, не повторяя их.

- GitHub-аккаунт, если код бота хранится там

## 2. Создание бота в Telegram

1. В Telegram напишите **[@BotFather](https://t.me/BotFather)**
2. Отправьте `/newbot`, следуйте инструкциям (имя бота, username)
3. BotFather пришлёт **токен** вида `123456789:AAExampleTokenFromBotFather` —
   сохраните его, он понадобится дальше. Токен — секретная вещь, как пароль:
   у кого он есть, тот полностью управляет ботом.
4. (Опционально, но полезно) В BotFather откройте **Bot Settings → Inline Mode**,
   включите и задайте текст-подсказку — это позволит вызывать бота из любого
   чата командой `@ИмяБота текст`, без добавления бота в этот чат.
5. Узнайте свой **Telegram user ID** через **[@userinfobot](https://t.me/userinfobot)**
   — пригодится, если в боте есть команды только для владельца (например, рассылка).

## 3. Код бота

Если код уже есть в GitHub-репозитории — просто клонируйте его (см. раздел 8).
Если создаёте с нуля — структура проекта (на примере этого бота):

```
blender_bot/
├── bot.py                  # точка входа, регистрация обработчиков
├── config.py                # переменные окружения, пути к данным
├── requirements.txt
├── .env.example              # шаблон, без реальных секретов
├── .gitignore                 # исключает .env, venv/, кэш
├── data/                       # JSON с контентом бота
├── handlers/                    # обработчики команд/сообщений
└── utils/                        # вспомогательная логика (поиск, переводчик и т.д.)
```

Ключевые уроки по коду, если пишете похожего бота:

- Храните токен и другие секреты только в `.env` (добавленном в `.gitignore`),
  никогда не коммитьте их в git
- Файлы, которые бот создаёт сам во время работы (логи, список подписчиков) —
  тоже добавляйте в `.gitignore`, они не должны попадать в репозиторий
- Если бот использует библиотеку `python-telegram-bot`, указывайте в
  `requirements.txt` **минимальную**, а не жёстко зафиксированную версию
  (`python-telegram-bot>=21.6`, а не `==21.6`) — так на новых версиях Python
  всегда подтянется совместимая сборка (см. проблему №1 в разделе 11)

## 4. Локальный запуск на Windows (для разработки)

1. Установите **Python** с [python.org](https://www.python.org/downloads/) —
   при установке обязательно отметьте **"Add python.exe to PATH"**

   > ⚠️ **Если у вас Windows поставила совсем свежую версию Python (например 3.14)**
   > — заранее знайте: некоторые библиотеки (в частности `python-telegram-bot`)
   > могут упасть с ошибкой `RuntimeError: There is no current event loop`.
   > Решение — либо `pip install --upgrade python-telegram-bot` (часто помогает),
   > либо поставить дополнительно Python 3.12 через `py -3.12` и создавать venv
   > именно на нём. Подробности — проблема №1 в разделе 11.

2. Откройте терминал в папке проекта: в Проводнике зайдите в папку, в адресной
   строке наберите `cmd`, нажмите Enter
3. Создайте виртуальное окружение и установите зависимости:

   ```
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   ```

4. Скопируйте `.env.example` в `.env`, впишите реальный токен
5. Запустите:

   ```
   python bot.py
   ```

   Строка `Бот запущен` в терминале — значит всё работает. Проверьте в Telegram
   командой `/start`.

Это годится для разработки и тестов, но бот работает только пока открыт
терминал. Дальше — как разместить его на сервере, чтобы он работал сам по себе.

## 5. Создание бесплатного сервера в Oracle Cloud

Используем **Oracle Cloud Free Tier** — там есть по-настоящему бесплатный
навсегда сервер (Always Free), которого достаточно для одного небольшого бота.

### 5.1 Регистрация

1. Зайдите на **[oracle.com/cloud/free](https://oracle.com/cloud/free)** →
   **Start for free**
2. Зарегистрируйтесь (email, телефон, карта для верификации — не списывает деньги
   с Always Free ресурсов)

### 5.2 Создание сервера (Compute Instance)

В консоли: ☰ меню → **Compute** → **Instances** → **Create Instance**.

**Basic information:**
- Name — можно оставить автоматическое, роли не играет
- Image — нажмите **Change image**, выберите **Ubuntu** (последняя LTS-версия,
  например 20.04 или 24.04)

**Shape:**
- Нажмите **Change shape**, выберите вариант с пометкой **Always Free-eligible**
  (обычно `VM.Standard.E2.1.Micro`)

**Security:**
- Ничего не меняйте, оставьте значения по умолчанию (Shielded instance выключен)

**Networking — самый проблемный шаг, читайте внимательно:**

1. **Primary network** → переключите на **Create new virtual cloud network**
   (если у вас ещё нет ни одной сети — это нормально для первого сервера)
2. **Subnet** → переключите на **Create new public subnet** (обязательно **public**)
3. Прокрутите вниз до **Public IPv4 address assignment** → включите
   **Automatically assign public IPv4 address**

   > ⚠️ **Известный баг:** этот переключатель у нас несколько раз не включался
   > (оставался серым), несмотря на то, что public subnet был выбран верно. Это
   > не ошибка пользователя, а глюк интерфейса Oracle. **Если не включается —
   > не тратьте на это время, создавайте сервер как есть, без публичного IP.**
   > Добавим его отдельно после создания сервера (шаг 5.4 ниже) — это работает
   > надёжнее, чем сам мастер создания.

**Add SSH keys:**
- Оставьте выбранным **Generate a key pair for me**
- Нажмите **Download private key** — скачается файл `.key`. **Сохраните его в
  отдельную, легко находимую папку** (например `C:\oracle-vps\`) — без него
  доступ к серверу восстановить нельзя

**Storage:**
- Ничего не меняйте, оставьте значения по умолчанию

Нажмите **Create**. Через 1-2 минуты статус сервера станет **Running**.

### 5.3 Если публичный IP не появился при создании

На странице сервера откройте вкладку **Сети (Networking)**. Если поле
**Общедоступный адрес IPv4** пустое — там же должен быть блок
**Экспресс-действия → «Подключение общедоступной подсети к Интернету»** с
кнопкой **Подключение**. Нажмите её — Oracle подключит интернет-шлюз и
настроит таблицу маршрутизации автоматически.

Если экспресс-действия нет или не помогло — добавьте IP вручную:

1. Вкладка **Сети** инстанса → нажмите на имя VNIC
2. Вкладка **Администрирование IP-адресов**
3. Найдите приватный адрес → значок ⋮ (три точки) → редактировать
4. **Тип общедоступного IP-адреса** → выберите **Динамический общедоступный
   IP-адрес** → **Обновить**

После этого на вкладке инстанса появится публичный IP — запишите его, он
понадобится для подключения по SSH.

## 6. Подключение к серверу по SSH

1. В Проводнике откройте папку со скачанным `.key`-файлом, в адресной строке
   наберите `cmd`
2. Подключитесь:

   ```
   ssh -i ssh-key-ИМЯФАЙЛА.key ubuntu@ВАШ_ПУБЛИЧНЫЙ_IP
   ```

   (пользователь именно `ubuntu`, если ставили образ Ubuntu)

3. На вопрос про fingerprint ("Are you sure you want to continue connecting?")
   ответьте `yes`

> ⚠️ **Частая ошибка на Windows: `UNPROTECTED PRIVATE KEY FILE`.**
> Windows по умолчанию даёт слишком открытые права на файл ключа. Лечится так
> (в обычном Windows-терминале, не на сервере):
>
> ```
> icacls ssh-key-ИМЯФАЙЛА.key /inheritance:r
> icacls ssh-key-ИМЯФАЙЛА.key /grant:r "%username%":R
> ```
>
> Если после этого ошибка осталась — проверьте, что реально удалось убрать:
>
> ```
> icacls ssh-key-ИМЯФАЙЛА.key
> ```
>
> Если в списке остались `BUILTIN\Administrators`, `NT AUTHORITY\SYSTEM`,
> `Authenticated Users` или `BUILTIN\Users` — уберите их явно:
>
> ```
> icacls ssh-key-ИМЯФАЙЛА.key /remove:g "BUILTIN\Administrators"
> icacls ssh-key-ИМЯФАЙЛА.key /remove:g "NT AUTHORITY\SYSTEM"
> icacls ssh-key-ИМЯФАЙЛА.key /remove:g "NT AUTHORITY\Authenticated Users"
> icacls ssh-key-ИМЯФАЙЛА.key /remove:g "BUILTIN\Users"
> ```
>
> Должна остаться только ваша учётная запись. Пробуйте подключаться заново.

> ⚠️ **Если SSH неожиданно обрывается** (`client_loop: send disconnect:
> Connection reset`) — это иногда бывает, особенно при первом подключении.
> Просто подключайтесь заново той же командой `ssh -i ...`.

Если увидели приглашение вида `ubuntu@instance-...:~$` — вы внутри сервера.

## 7. Установка Python и окружения на сервере

### 7.1 Обновление системы и git

```
sudo apt update && sudo apt upgrade -y
sudo apt install -y git
```

### 7.2 Установка Python 3.11 через pyenv

Проверьте версию системного Python:

```
python3 --version
```

Ubuntu 20.04 обычно ставит Python 3.8 — этого мало для современных версий
`python-telegram-bot` (нужен минимум 3.9-3.10, лучше 3.11).

> ⚠️ **Не тратьте время на deadsnakes PPA.** Стандартный совет в интернете —
> поставить нужную версию Python через `add-apt-repository ppa:deadsnakes/ppa`.
> У нас этот путь трижды ломался (пакет "находился" в репозитории, но
> `apt install` не мог его увидеть — кэш apt не докачивал список пакетов).
> Чинится через `sudo rm -rf /var/lib/apt/lists/* && sudo apt update`, но
> результат нестабилен. **Сразу используйте pyenv** — он не зависит от
> репозиториев Ubuntu и просто компилирует Python из исходников.

Установите инструменты для сборки и сам pyenv:

```
sudo apt install -y build-essential zlib1g-dev libncurses5-dev libgdbm-dev libnss3-dev libssl-dev libreadline-dev libffi-dev libsqlite3-dev wget libbz2-dev liblzma-dev
sudo apt install -y screen
curl -fsSL https://pyenv.run | bash
```

Добавьте pyenv в переменные окружения — **одной командой**, не по одной строке
через несколько `echo`:

> ⚠️ Если писать три отдельные команды `echo '...' >> ~/.bashrc` одну за
> другой — при вставке в терминал строки могут "слипнуться" без переноса
> (например, `~/.bashrcecho`), и `.bashrc` испортится с ошибкой синтаксиса при
> следующем открытии терминала. Используйте один `printf`:

```
printf '\nexport PYENV_ROOT="$HOME/.pyenv"\n[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"\neval "$(pyenv init -)"\n' >> ~/.bashrc
source ~/.bashrc
pyenv --version
```

Если `.bashrc` всё же оказался повреждён (ошибка `syntax error near unexpected
token` при `source`), почистите дубликаты и пересоздайте блок:

```
sed -i '/PYENV_ROOT/d; /pyenv init/d; /pyenv virtualenv-init/d' ~/.bashrc
printf '\nexport PYENV_ROOT="$HOME/.pyenv"\n[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"\neval "$(pyenv init -)"\n' >> ~/.bashrc
source ~/.bashrc
```

### 7.3 Компиляция Python — обязательно внутри `screen`

> ⚠️ Компиляция Python на слабом сервере занимает **10-15 минут**. Если за это
> время оборвётся SSH-соединение (а на первых порах оно обрывается часто) —
> процесс компиляции **умрёт вместе с закрытым терминалом**, и всё придётся
> начинать заново. Чтобы это не повторилось — обязательно запускайте
> установку внутри `screen`, программы, которая держит процессы живыми на
> сервере независимо от вашего SSH-окна.

```
screen -S pyenv_install
pyenv install 3.11.9
```

Дождитесь строки `Installed Python-3.11.9 to /home/ubuntu/.pyenv/versions/3.11.9`.

Если SSH оборвётся во время ожидания — просто переподключитесь и вернитесь к
сессии:

```
ssh -i ssh-key-ИМЯФАЙЛА.key ubuntu@ВАШ_IP
screen -r pyenv_install
```

Если пишет `There is no screen to be resumed... (Attached)` — добавьте флаг
`-d`, который принудительно отключает старое мёртвое подключение:

```
screen -d -r pyenv_install
```

После успешной установки:

```
pyenv global 3.11.9
python3 --version
```

Должно показать `Python 3.11.9`. Выйдите из screen обычной командой `exit`.

## 8. Разворачивание бота на сервере

### 8.1 Скачать код

```
git clone -b ИМЯ_ВЕТКИ https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git
cd ВАШ_РЕПОЗИТОРИЙ/blender_bot
```

### 8.2 Виртуальное окружение и зависимости

```
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

В начале строки терминала должно появиться `(venv)`.

### 8.3 Настройка `.env`

```
nano .env
```

Впишите (замените на реальные значения):

```
BOT_TOKEN=ваш_настоящий_токен_от_botfather
OWNER_ID=ваш_telegram_id
```

**Сохраняйте строго в этом порядке:**

1. **Ctrl+O**, затем **Enter** (сохранить)
2. Только затем **Ctrl+X** (выйти)

> ⚠️ Если закрыть терминал/окно раньше, чем нажать Ctrl+O → Enter → Ctrl+X —
> файл не сохранится. **Обязательно проверяйте после сохранения:**
>
> ```
> cat .env
> ```
>
> Должны увидеть обе строки. Если `cat: .env: No such file or directory` —
> значит не сохранилось, повторите `nano .env` заново.

> ⚠️ Если при повторном открытии nano пишет `File .env is being edited by
> ubuntu (with nano ..., PID ...); open anyway?` — это безобидное
> предупреждение об оставшемся "зависшем" процессе от прошлой попытки.
> Смело жмите **Y**.

### 8.4 Тестовый запуск

```
python bot.py
```

Строка `Бот запущен` и `Application started` — значит всё работает. Проверьте
в Telegram: `/start`. Остановите тестовый запуск клавишами **Ctrl+C** перед
следующим шагом.

## 9. Автозапуск через systemd

Это финальный шаг, который делает бота по-настоящему автономным — он будет
работать даже после закрытия терминала и перезагрузки сервера.

```
sudo nano /etc/systemd/system/blenderbot.service
```

Вставьте (замените пути на свои, если отличаются — узнать текущий путь можно
командой `pwd`, находясь в папке бота):

```
[Unit]
Description=Blender Telegram Bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/ВАШ_РЕПОЗИТОРИЙ/blender_bot
ExecStart=/home/ubuntu/ВАШ_РЕПОЗИТОРИЙ/blender_bot/venv/bin/python /home/ubuntu/ВАШ_РЕПОЗИТОРИЙ/blender_bot/bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Сохраните: **Ctrl+O → Enter → Ctrl+X**. Проверьте содержимое (`cat
/etc/systemd/system/blenderbot.service`) — так же, как с `.env`.

Включите и запустите службу:

```
sudo systemctl daemon-reload
sudo systemctl enable blenderbot
sudo systemctl start blenderbot
sudo systemctl status blenderbot
```

Должно быть **Active: active (running)** и **enabled**. Готово — можно
закрывать терминал и выключать компьютер, бот продолжит работать.

## 10. Указатель по официальному руководству Blender

Дополнительно бот умеет подсказывать ссылки на официальную документацию
Blender (docs.blender.org) для тем, которых нет в собственной базе знаний.
Это отдельный шаг, не обязательный — бот прекрасно работает и без него.

Индекс собирается скриптом `scripts/build_manual_index.py`: он клонирует
открытый исходник документации (`projects.blender.org/blender/blender-manual`
— собственный self-hosted git Blender Foundation, лицензия CC-BY-SA; старое
зеркало на github.com/blender/blender-manual больше не существует), достаёт
заголовок и краткое описание каждой страницы и сохраняет в
`data/manual_index.json`. Для сборки нужен интернет — запускать **на сервере**,
не локально в изолированных средах (некоторые песочницы блокируют доступ к
внешним git-хостингам и docs.blender.org).

> ⚠️ Если `git clone` вдруг зависает на запросе `Username for
> 'https://...'` — это значит адрес репозитория недоступен (переехал/удалён),
> а не проблема с сетью или правами: GitHub и подобные хостинги нарочно не
> отличают «репозитория не существует» от «нет доступа» и на оба случая
> просят логин. Открой адрес репозитория в обычном браузере, чтобы проверить
> актуальный путь.

На сервере, внутри активированного `venv`:

```
cd ~/ВАШ_РЕПОЗИТОРИЙ/blender_bot
python scripts/build_manual_index.py
```

Клонирование и разбор нескольких тысяч страниц может занять пару минут —
если боитесь обрыва SSH, запускайте внутри `screen` (см. раздел 7.3).

После завершения перезапустите бота, чтобы он подхватил новый файл:

```
sudo systemctl restart blenderbot
```

Файл `data/manual_index.json` не хранится в git (слишком большой,
перегенерируется на месте) — при переезде на новый сервер скрипт нужно будет
запустить заново.

## 11. Шпаргалка команд на каждый день

Подключение к серверу:
```
ssh -i ssh-key-ИМЯФАЙЛА.key ubuntu@ВАШ_IP

```

sudo systemctl restart blenderbot

## 12. Сводка всех проблем и решений

| № | Проблема | Причина | Решение |
|---|---|---|---|
| 1 | `RuntimeError: There is no current event loop` при запуске бота на Windows | Слишком новая версия Python (3.14) несовместима с библиотекой | `pip install --upgrade python-telegram-bot`, либо venv на Python 3.12 |
| 2 | Переключатель "Automatically assign public IPv4 address" не включается при создании сервера | Известный глюк интерфейса Oracle Cloud | Создать сервер без IP, добавить публичный IP отдельно через вкладку "Сети" уже созданного инстанса |
| 3 | `UNPROTECTED PRIVATE KEY FILE` при SSH с Windows | Слишком открытые NTFS-права на файл ключа | `icacls` — убрать все права кроме своей учётной записи (см. раздел 6) |
| 4 | `E: Unable to locate package python3.11` из deadsnakes PPA | Повреждённый/недокачанный кэш apt | Использовать pyenv вместо PPA (см. раздел 7.2) |
| 5 | Процесс компиляции Python обрывается при разрыве SSH | Процесс без защиты завершается вместе с закрытым терминалом | Запускать долгие операции внутри `screen` |
| 6 | `screen -r` пишет "no screen to be resumed... (Attached)" | Screen-сессия осталась помечена как подключённая к мёртвому терминалу | `screen -d -r ИМЯ_СЕССИИ` (флаг `-d` принудительно отключает старое) |
| 7 | Синтаксическая ошибка в `.bashrc` при `source ~/.bashrc` | Несколько отдельных `echo`-команд "слиплись" при вставке в терминал | Добавлять переменные одной командой `printf`, не несколькими `echo` |
| 8 | `.env` или файл systemd-службы не сохраняется в nano | Терминал закрыт раньше, чем завершена последовательность сохранения | Строго Ctrl+O → Enter → Ctrl+X, затем проверять `cat` |
| 9 | Скрипт сборки указателя по документации (`build_manual_index.py`) не работает в изолированных ассистент-песочницах | Такие среды часто блокируют исходящий доступ к GitHub/сторонним сайтам | Запускать скрипт именно на сервере — там полноценный интернет |
| 10 | `git clone` зависает на "Username for 'https://github.com'" при сборке указателя | Репозиторий переехал/удалён — GitHub так реагирует и на несуществующий, и на приватный репозиторий | Проверить актуальный адрес в браузере (blender-manual переехал на projects.blender.org) |
