# Sentry — рекомендация (не установлено)

Проверено перед написанием этого файла: `sentry`/`sentry-sdk` не
встречается нигде в коде проекта (`bot/`, `search/`, `knowledge/`,
`profile/`, `diagnostics/`, `education/`, `scripts/`) и не значится в
`requirements.txt`. Sentry сейчас **не установлен и не подключён** —
этот файл только рекомендация, сам Sentry не устанавливался.

Проект действительно имеет production-пользователей: `@Blenderhelpbot`
работает на Oracle Cloud 24/7 и обслуживает реальных людей в Telegram
(см. `DEPLOYMENT.md`), так что мониторинг ошибок в принципе осмысленен —
вопрос только в том, стоит ли он объёма работы и что именно отправлять.

## Что даст Sentry этому боту

- **Видимость необработанных исключений в реальном времени** — сейчас
  единственный способ узнать о падении хендлера это либо
  `sudo journalctl -u blenderbot -f` вручную на сервере, либо жалоба
  пользователя в чате. Sentry присылал бы уведомление сразу, с полным
  traceback и частотой повторения.
- **Группировка похожих ошибок** — если один и тот же баг ловит
  несколько разных пользователей, сейчас это выглядит как N отдельных
  строк в логе; Sentry схлопнул бы их в одно событие со счётчиком.
- **Контекст без ручного `/debug`** — `bot/handlers/admin.py::debug_command`
  уже даёт `/debug <вопрос>` для ручной диагностики ОДНОГО вопроса
  постфактум; Sentry ловил бы это автоматически в момент сбоя, без
  необходимости, чтобы владелец сам додумался переспросить пользователя,
  что тот вводил.

## Что потребуется изменить

- Добавить `sentry-sdk` в `requirements.txt` (лёгкая, чистая Python-
  зависимость, не требует внешнего процесса/демона — не нарушает раздел
  2 ТЗ про "без внешнего LLM/AI", это просто observability-библиотека).
- Инициализация в `app/main.py` — несколько строк `sentry_sdk.init(dsn=...)`
  до `Application.builder()`.
- `SENTRY_DSN` — новая переменная в `.env`/`.env.example`, читается через
  `config/__init__.py` тем же способом, что `BOT_TOKEN`/`OWNER_ID`.
- Явный `before_send` hook (см. ниже) — обязателен, не опциональная
  доработка "на будущее", иначе PII улетает в третий сервис по
  умолчанию.
- Нужен бесплатный Sentry-аккаунт (free tier: 5000 событий/месяц —
  для одного маленького бота более чем достаточно) и DSN-ключ — это
  единственный внешний сервис, который потребуется завести.

## Какие данные будут отправляться

По умолчанию `sentry-sdk` с интеграцией под `python-telegram-bot`
захватывает: traceback, имя файла/строку/функцию, значения локальных
переменных в кадрах стека, и — это важно — **текст последнего
HTTP-запроса/апдейта**, если не сконфигурировано иначе. Для Telegram-бота
это означает, что **сырой текст сообщения пользователя** может попасть в
`update.message.text` внутри локальных переменных стека и уйти в Sentry
по умолчанию. Дополнительно: IP сервера (не пользователя — Sentry видит
только сервер, с которого шлётся событие), версия Python/зависимостей,
таймстемпы, счётчики частоты.

## Как НЕ отправлять пользовательский текст/секреты

Обязательный `before_send` перед любым включением в проде:

```python
def _scrub_event(event, hint):
    # Не пускаем сырой текст сообщений пользователей и токен в Sentry.
    for frame in event.get("exception", {}).get("values", [{}])[0].get(
        "stacktrace", {}
    ).get("frames", []):
        frame.get("vars", {}).pop("question", None)
        frame.get("vars", {}).pop("text", None)
        frame.get("vars", {}).pop("update", None)
    return event

sentry_sdk.init(dsn=SENTRY_DSN, before_send=_scrub_event, send_default_pii=False)
```

Плюс: `send_default_pii=False` (по умолчанию и так `False` в актуальных
версиях SDK, но стоит явно зафиксировать, а не полагаться на дефолт),
никогда не логировать `BOT_TOKEN`/`.env`/SSH-путь в контексте события —
Sentry SDK сам не подхватывает переменные окружения автоматически, но
любой явный `sentry_sdk.set_context(...)`/`set_tag(...)` в коде должен
пройти тот же самый ревью, что и сам `before_send`.

Более простой, но грубее, вариант: явно выключить захват breadcrumbs с
содержимым HTTP-тел (`Sentry.init(..., max_breadcrumbs=0)` или отдельная
интеграция без `PytelegrambotIntegration`, если такая существует в
актуальной версии SDK на момент подключения — стоит перепроверить перед
установкой, SDK меняется).
