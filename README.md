# True Thrills

Первая устанавливаемая веб-версия авторской студии и приложения слушателя.

## Что реализовано

- Запись с выбранного аудиоустройства Windows, выбор входа 1 или 2 с преобразованием в моно, отключение автоматической обработки браузера.
- Индикатор реального сигнала, пауза, остановка и прослушивание. Запись Opus/WebM или MP4 — в зависимости от браузера. Для исходников без сжатия используйте DAW и загрузку WAV.
- Последний аудиочерновик сохраняется локально в IndexedDB. Его можно скачать или загрузить в серверное хранилище. Максимум 80 МБ на файл; автоматическая остановка записи около 75 МБ.
- Серверные черновики и публикация подкастов и историй. Редактирование, снятие с публикации и удаление с подтверждением. Аудио поддерживает HTTP Range и Media Session.
- Локальное восстановление текста новой истории. Это не заменяет серверное сохранение черновика.
- Прямое аудиовещание WebRTC с серверным обменом предложениями соединения. Пилот на 8 слушателей, без автоматической записи эфира.
- Внешняя платёжная ссылка, настраиваемая автором. Приложение не обрабатывает платежи и не ведёт статистику поступлений.
- Адаптивный интерфейс и PWA-манифест для установки из поддерживаемого браузера. Также доступны Windows x64 клиент WebView2 с EXE-установщиком и Android 8+ APK-клиент слушателя — полноэкранный WebView без видимой панели браузера, с нативными push-уведомлениями через Firebase Cloud Messaging.

## Развёртывание на своём сервере (VPS)

Приложение — обычное Node.js-приложение (Next.js App Router), без привязки к Cloudflare или ChatGPT. Данные хранятся в файле SQLite, аудио — в локальной папке на диске.

1. Скопируй `.env.example` в `.env`, задай `ADMIN_PASSWORD` (пароль автора) и `SESSION_SECRET` (случайная строка, `openssl rand -base64 32`).
2. `npm ci`
3. `npm run db:migrate` — создаёт файл базы данных и таблицы.
4. `npm run build && npm start` (или через systemd/pm2, слушает `PORT`, по умолчанию 3000).
5. Пусти перед приложением реверс-прокси (nginx/Caddy) с HTTPS — сессионная cookie помечена `Secure` и требует HTTPS в продакшене.
6. Пропиши свой домен в `desktop/client.cpp` (`SITE`/`VIEWER`) и `android/app/src/main/java/com/truethrills/listener/MainActivity.java` (`BASE`), затем пересобери десктоп-клиент и APK — иначе они продолжат стучаться на старый адрес `chatgpt.site`.

## Первый запуск

Открой `/login` и войди паролем из `ADMIN_PASSWORD`, затем нажми «Открыть мою студию». Единственный аккаунт-автор закрепляется на сервере один раз; все изменяющие запросы проверяют его. Слушателям аккаунт не нужен — раздел подкастов/историй/эфира открыт всем по ссылке.

В студии разрешите микрофон, затем выберите Komplete Audio 6 и нужный вход. Перед первой записью нажмите «Разрешить микрофон и найти устройства». Уровень регулируется на предусилителе и аудиоинтерфейсе; программное усиление, выключение микрофона и фильтр 80 Гц доступны в студии и эфире. Выбор физического устройства и правильность кабельного подключения нельзя проверить из среды разработки.

## Перед публичным запуском

1. Проверить запись на Windows с реальным SM7B, воспроизведение и установку на Android, в том числе блокировку экрана. Media Session не гарантирует фоновую работу во всех браузерах.
2. Подключить доступ аудитории к приложению; текущее развёртывание — приватное. Проверить, что автор уже закреплён. Слушателям не нужны права редактирования.
3. Заменить пилотный WebRTC fan-out полноценным сервером вещания (SFU или аудиостриминг), настроить TURN, ограничения запросов и нагрузочные проверки. Нынешний режим использует STUN; некоторые NAT и мобильные сети не позволят подключиться. В текущем режиме IP-адреса соединения могут быть доступны участникам.
4. Добавить платёжную ссылку выбранного автором сервиса. Проверить аккаунт и реальное зачисление непосредственно у провайдера.
5. Настроить резервное копирование, обработку неиспользуемых загрузок, правила хранения и эксплуатационные лимиты.

Приватная публикация не означает готовности к коммерческому запуску. Работа с реальными устройствами, фоновой записью, сном Windows и мобильными сетями в среде разработки не проверена.

## Техническая основа

React / Next.js (App Router) / TypeScript. SQLite (better-sqlite3 + drizzle-orm) для публикаций и сигналинга эфира, локальная папка на диске (`STORAGE_DIR`) для аудио. Вход — пароль автора (`ADMIN_PASSWORD`) и подписанная сессионная cookie (`lib/auth.ts`); слушатели заходят без аккаунта. История миграций — `drizzle/`.

Проверка типов: `node_modules/.bin/tsc --noEmit`.

Проверки API без выхода в интернет: `node tests/api-integration.mjs` (запускается автоматически в `npm test`). Проверяются авторизация, приватность черновиков, публикация, загрузка и диапазоны аудио, проверка платёжных ссылок, жизненный цикл эфира, изоляция токенов подключения и удаление файлов. Они не имитируют реальный микрофон или соединение двух устройств.


## Изменения 0.2.0

- Баннер активного эфира во всех разделах, отдельный лёгкий запрос статуса каждые 3 секунды и при возвращении к окну. Запросы не перекрываются; ошибки обновления видны пользователю.
- Ссылка `/?mode=listen&view=live` открывает слушателя независимо от роли аккаунта. Во время эфира просмотр слушателя открывается в другом окне и не отключает микрофон автора.
- Завершённый эфир передаёт слушателям `active: false`; запоздалые heartbeat не возобновляют остановленную трансляцию. Период допустимого отсутствия heartbeat увеличен до 90 секунд. Подключение автора и передача звука всё ещё требуют стабильной сети.
- Windows-клиент WebView2: отдельное окно, запрос разрешения на микрофон только для собственного адреса, подтверждение закрытия при записи/эфире, предотвращение сна во время активной записи/эфира. Внешние ссылки открываются в браузере.
- Установщик для текущего пользователя создаёт ярлыки и запись в «Установленные приложения». Удаление сохраняет серверные публикации и локальную папку данных `%LOCALAPPDATA%\TrueThrills`.

## Windows-сборка

Исходники находятся в `desktop/`. Сборка: Python 3, Zig 0.13.0 и официальный Microsoft WebView2 SDK 1.0.2903.40 (скачивается сборщиком с проверкой SHA256).

`python3 desktop/build.py --zig /path/to/zig --output /path/to/output`

`python3 desktop/verify.py /path/to/output`

Установщик `TrueThrills-Setup-0.2.0.exe` содержит клиент и официальный WebView2Loader.dll с лицензией. На Windows требуется установленный WebView2 Runtime. При его отсутствии приложение предлагает открыть официальную страницу Microsoft. Клиент подключается к существующему серверу; доступ для аудитории остаётся приватным. Вход проходит штатным способом через ChatGPT, без встроенных паролей или обхода авторизации. Некоторые провайдеры входа запрещают встроенные окна; в меню есть открытие веб-версии в браузере.

EXE не подписан сертификатом издателя. Проверены компиляция, PE x64/GUI, манифест без повышения прав, ресурсы и побайтовое соответствие вложений установщика. Запуск, установка/удаление и авторизация на настоящем Windows ещё не проверены.


## Изменения 0.3.0

- Названия аудиовходов запрашиваются после отдельного разрешения на микрофон, до записи. Временный поток закрывается даже при ошибке перечисления. Поддерживается обновление списка при подключении устройств.
- Эфир автора: реальный индикатор сигнала, таймер, статус сервера, выбор устройства и канала до начала; усиление −18…+12 dB, выключение микрофона и high-pass 80 Гц во время вещания. Те же настройки применяются к записи подкастов.
- Слушатель: отдельные состояния подключения, фактического воспроизведения, паузы, блокировки автозапуска и потери связи; уровень входящего звука, громкость, пауза и повторное подключение. «Вы в эфире» не выставляется по одному факту получения SDP/трека.
- Удалены статичный блок оборудования и неработающие кнопки установки. Windows-клиент получает интерфейс с сервера при следующем открытии.
- Android APK открывает приложение сразу в режиме слушателя. Это начальный онлайн-клиент через Chrome Custom Tabs, с видимой панелью браузера и обычным входом ChatGPT. Нативный автономный плеер, офлайн-загрузки и push-уведомления не реализованы. Публичный доступ не изменён: для текущего теста на телефоне требуется аккаунт владельца.

Проверка регрессии обнаружения микрофонов: `node tests/device-discovery.mjs`.

## Android-сборка

Исходники находятся в `android/`; package `com.truethrills.listener`, minSdk 26, targetSdk 35. Разрешения: INTERNET и POST_NOTIFICATIONS (для push); запись голоса на Android не запрашивается. Launcher — полноэкранный `WebView` (без адресной строки), с мостом `AndroidPush` для нативных push-уведомлений через Firebase Cloud Messaging (`PushService.java`, `PushClient.java`) — см. «Push через Firebase» в `docs/RELEASE-0.5-RU.md`.

Сборка — стандартный Gradle (`com.android.application` + `com.google.gms.google-services`), требует сеть до `google()`/Maven и `google-services.json` в `android/app/` — в этой рабочей среде недоступно, поэтому сборка идёт через GitHub Actions (`.github/workflows/android-build.yml`, кнопка «Run workflow»). Нужны секреты репозитория: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `GOOGLE_SERVICES_JSON_BASE64`.

Для локальной сборки (например, в Android Studio):

```sh
gradle -p android assembleRelease
```

Ключ выпуска и пароль НЕ входят в исходники. Для обновлений используйте тот же ключ из приватного архива `TrueThrills-Android-Signing-Backup.zip`; увеличивайте versionCode. Архив содержит пароль и предназначен только владельцу/разработчику: его нельзя раздавать слушателям. Установка на реальный Android, вход, получение живого звука, доставка push и работа с заблокированным экраном требуют проверки на телефоне.

## Упрощение слушателя 0.3.1

Уведомление об эфире стало одной большой кнопкой: нажатие сразу открывает плеер и начинает подключение в том же пользовательском действии. Если слушатель уже подключён, переход сохраняет текущий сеанс; на паузе — возобновляет его. Повторное нажатие не создаёт второй сеанс. Главная кнопка находится выше волны и громкости; ожидание видно сразу. Техническая шкала dBFS оставлена автору. Android APK и Windows EXE получают изменение с сервера без переустановки.


## Плеер и фирменное оформление 0.4.0

- Предоставленный владельцем логотип сохранён в `public/brand/true-thrills-original.png`. Из него подготовлены размеры для интерфейса, обложки системного плеера, favicon, PWA, ICO Windows и адаптивная иконка Android. Рисунок не перерисовывался; исходник сохранён полностью.
- Плеер подкаста показывает текущее время, длительность, полосу перемотки, паузу и переходы ±15 секунд. Команды системного медиаплеера используют ту же аудиозапись.
- Записи MediaRecorder в WebM могут не содержать Duration/Cues. При остановке записи и восстановлении локального черновика файл проходит подготовку в Web Worker. Mediabunny 1.55.7 пересобирает контейнер с длительностью и индексом, копируя закодированные пакеты без декодирования и повторного сжатия.
- При прослушивании старого опубликованного WebM без конечной длительности плеер загружает исходник и готовит временную исправленную копию на устройстве. Исходная публикация не перезаписывается. Перед первым воспроизведением такого файла возможна задержка; нужны интернет и место в памяти. Выход из плеера отменяет загрузку и обработку.
- Длительность новых загружаемых файлов читается из аудиодорожки. Корректные WebM и другие аудиоформаты не пересобираются. Если подготовка нового черновика не удалась, исходник сохраняется и выводится предупреждение.
- Windows installer: `TrueThrills-Setup-0.4.0.exe`; Android package/version: `com.truethrills.listener`, versionCode 4 / versionName 0.4.0. Android подписан исходным ключом выпуска, поэтому устанавливается поверх 0.3.0. Windows устанавливается в прежнюю папку и сохраняет данные пользователя. Для замены иконок необходимо установить новые пакеты.

Проверка аудио: `node tests/audio-file.mjs` (требуются ffmpeg/ffprobe). Тест воспроизводит отсутствующую длительность потокового WebM, проверяет конечную длительность, Cues, декодирование после перемотки и полное совпадение хешей исходных аудиопакетов; также проверяет MP3, повторную подготовку и повреждённый файл. Проверены TypeScript, production-сборка с отдельным Worker, подпись Android и Windows-ресурсы/вложения установщика. Новые пакеты и интерфейс не запускались на физических Windows/Android в среде разработки.

Ссылки по реализации: https://mediabunny.dev/guide/reading-media-files , https://mediabunny.dev/guide/writing-media-files , https://www.matroska.org/technical/cues.html .
