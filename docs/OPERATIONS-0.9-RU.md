# True Thrills — сервер и PowerShell для 0.9

Эта инструкция заменяет обновление из 0.8. Домен: https://truethrills.com. По передаче владельца VPS — ubuntu@129.152.8.230, каталог /opt/truethrills. Сначала проверить, что это действительно текущий сервер. Нужен уже настроенный SSH-доступ; пароль/ключ не отправлять в чат.

## Обновление с Windows

Распакуй полный архив исходников. Открой PowerShell в каталоге TrueThrills, где лежат package.json и папка scripts. Команды ниже запускаются на твоём ПК; серверные команды скрипт отправляет через SSH.

```powershell
$Key = Read-Host 'Путь к твоему SSH-ключу; Enter, если вход уже работает без указания ключа'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\TrueThrills-Server.ps1 -Action Status -KeyPath $Key
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\TrueThrills-Server.ps1 -Action Update -KeyPath $Key
```

Если SSH-аккаунт другой, добавь `-Server 'имя@адрес'`. Для установки строго проверенного commit добавь `-ExpectedCommit 'полный SHA из финальной передачи'`. Рабочая ветка — truethrills-app. Скрипт не требует оставлять PowerShell или ПК включённым после завершения: службы работают на VPS через systemd.

Что делает Update: проверяет чистоту отслеживаемого кода и возможность fast-forward; получает целевой commit; запрещает обновление в активном эфире; устанавливает FFmpeg, если его нет; останавливает службы; делает проверенную копию до изменения схемы; обновляет зависимости/код, собирает, применяет миграции; включает LIVE_ENABLED и службы/таймеры; проверяет health. `.env` не заменяется файлом из архива. Оригинальный ключ подписи APK сохраняется.

Если ветки разошлись или есть локальные изменения, исправлять это нужно с Claude, сохраняя работу; не применять reset --hard. Если обновление после изменения кода не удалось, службы остаются остановленными и выводится предыдущий SHA. Не повторять миграции вслепую: сначала определить причину или восстановить совместимую пару кода и БД.

## Копия на ПК

После успешного обновления, вне эфира:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\TrueThrills-Server.ps1 -Action Backup -KeyPath $Key
```

Результат — приватный `.tar.gz` в Documents\TrueThrills-Backups. Скрипт сравнивает SHA256 скачанного файла с серверным и лишь затем удаляет временный файл передачи. Основная серверная копия остаётся. Ключ Android не извлекается из GitHub Secrets: его отдельная приватная копия должна храниться у владельца.

Резервирование включает БД, audio storage, принятые live-фрагменты/выходы, .env как server.env, внешний Firebase JSON и RESTORE-PATHS.json с исходными путями. Копия содержит секреты; передавать её публично или прикладывать к общему исходному коду нельзя. При отсутствии доступа к Firebase JSON копия не помечается успешно завершённой.

Проверка контрольной суммы доказывает целостность передачи. Следующий обязательный шаг — изолированное восстановление реальных данных и проигрывание аудио. Автоматически скачивать копии на выключенный ПК нельзя; VPS выполняет свои копии без ПК, а скачивание запускается, когда ПК включён.

## Проверка служб через PowerShell

```powershell
ssh -i $Key ubuntu@129.152.8.230
```

Если ключ не нужен, использовать `ssh ubuntu@129.152.8.230`. После входа команды уже Linux:

```bash
cd /opt/truethrills
systemctl status truethrills truethrills-live --no-pager
systemctl list-timers 'truethrills-*' --no-pager
curl -fsS https://truethrills.com/api/health
sudo journalctl -u truethrills-live -n 60 --no-pager
```

Не публиковать полный журнал, если в нём есть личные сведения. Успешный health должен показывать ok=true, version=0.9.1, liveWorker=true. Начни эфир, дождись звука на телефоне, заверши, дождись готовой записи и проверь её после выключения ПК.

## Обновление 0.9.1: сервисы переезжают с root

Это обновление меняет не только код. Появляется системный пользователь
`truethrills`, ему передаётся каталог `/opt/truethrills` и каталог бэкапов, и
от его имени начинают работать приложение, воркер эфира и мониторинг. Делать
это с телефона не нужно: если что-то пойдёт не так, сайт останется лежать до
ручного вмешательства.

Порядок: не в эфире, за компьютером, обычной командой `Update` — она сама
вызовет `install-operations.sh`, который создаёт пользователя, передаёт
владение и переписывает все четыре юнита.

После обновления проверить, что процессы действительно сменили владельца:

```bash
systemctl show truethrills truethrills-live truethrills-monitor -p User
ps -o user= -p "$(systemctl show -p MainPID --value truethrills)"
ls -ld /opt/truethrills /opt/truethrills/data /var/backups/truethrills
curl -fsS https://truethrills.com/api/health
```

Ожидается `User=truethrills` у всех трёх, тот же пользователь у живого
процесса, и владелец `truethrills` у всех трёх каталогов. У
`truethrills-backup` пользователь остаётся root — он вызывает systemctl, это
административная операция.

Затем обязательно проверить руками то, что правами не проверяется: загрузку
выпуска, обложку, эфир от начала до готовой записи и ежедневный бэкап (можно
не ждать сутки: `sudo systemctl start truethrills-backup.service`, потом
`journalctl -u truethrills-backup -n 40 --no-pager`). Мониторинг читает
каталог бэкапов от имени сервиса — если он вдруг сообщит о пропаже копий,
значит владение каталогом не передалось, и это чинится
`sudo chown -R truethrills:truethrills /var/backups/truethrills`.

Откат, если приложение не поднялось: вернуть прежний юнит без `User=` и
перезапустить.

```bash
sudo systemctl edit --full truethrills   # убрать строки User=/Group=
sudo systemctl daemon-reload && sudo systemctl restart truethrills
```

Это временная мера на один вечер: правка юнита исчезнет при следующем
обновлении, потому что юниты переписываются каждый раз. Причину надо найти —
почти всегда это права на файл, который сервис не может прочитать или
записать, и виден он в `journalctl -u truethrills -n 80 --no-pager`.

## Восстановление

До любых действий записать текущий SHA и пути. Сохранить неисправное состояние отдельно для диагностики. Остановить truethrills и truethrills-live. Распаковать backup в отдельный приватный каталог, выполнить verify-backup.mjs, проверить RESTORE-PATHS.json. Возвращать БД вместе с подходящим кодом; не оставлять старые WAL/SHM рядом с восстановленной БД. Восстановить storage/live, server.env в .env, Firebase JSON по указанному пути и правильные права пользователя службы. После запуска проверить публикации и несколько записей. Если backup до миграции 0006, к нему нужен совместимый старый код либо осознанное применение миграций на восстановленной копии.

Проверенный backup не удалять до успешной приёмки. Удаление старых резервных копий/исходных фрагментов автоматически не настроено: сначала выбрать срок хранения и подтвердить копию вне VPS. Монитор сигнализирует о низком месте; новый эфир блокируется при запасе менее 1 ГиБ.

## Что ещё нужно включить владельцу

Внешний независимый монитор доступности и адрес для оповещения пока не заданы. MONITOR_WEBHOOK_URL — опциональный HTTPS endpoint, принимающий JSON checkedAt/ok/issues. Секрет в URL держать только в .env. Это не готовая интеграция Telegram/почты и не доказательство доставки сообщений. Настройка адреса и испытание выбранного канала остаются обязательными перед широким запуском.

## Обновление сервера с телефона (Termux)

Когда компьютера под рукой нет. Ставится один раз, дальше — одно слово.

### Один раз

Termux бери с F-Droid: версия из Google Play давно не обновляется и ломается
на новых Android.

```
pkg update && pkg upgrade -y
pkg install openssh -y
termux-setup-storage
```

Ключ на телефон переноси сам — по кабелю или своим облаком. Через переписку
и мессенджеры его отправлять нельзя. Положи в «Загрузки» и перенеси к себе:

```
mkdir -p ~/.ssh
cp /sdcard/Download/ssh-key-2026-09-06.key ~/.ssh/truethrills.key
chmod 600 ~/.ssh/truethrills.key
rm /sdcard/Download/ssh-key-2026-09-06.key
```

Последняя строка обязательна: папка «Загрузки» открыта другим приложениям, а
каталог Termux — нет.

Проверка связи:

```
ssh -i ~/.ssh/truethrills.key ubuntu@129.152.8.230 "echo OK"
```

Команды одним словом:

```
cat >> ~/.bashrc <<'EOF'
tt-update(){ termux-wake-lock; ssh -i ~/.ssh/truethrills.key ubuntu@129.152.8.230 "cd /opt/truethrills && sudo bash .update-staging/update-safe.sh design/six-screens"; termux-wake-unlock; }
tt-status(){ ssh -i ~/.ssh/truethrills.key ubuntu@129.152.8.230 "cd /opt/truethrills && git log -1 --format=%H && systemctl is-active truethrills && curl -fsS http://127.0.0.1:3000/api/health"; }
tt-clean(){ ssh -i ~/.ssh/truethrills.key ubuntu@129.152.8.230 "cd /opt/truethrills && sudo node --env-file=.env scripts/prune-live-posts.mjs $1"; }
EOF
source ~/.bashrc
```

### Каждый раз

```
tt-update
```

Ждёт пару минут и заканчивается строкой `Updated successfully to …`.
`termux-wake-lock` внутри не даёт телефону уснуть на середине сборки.

Посмотреть, что сейчас на сервере: `tt-status`.
Показать записи эфиров без строки эфира: `tt-clean`, удалить их:
`tt-clean --delete`.

## Если приложение не открывается ни на ПК, ни на телефоне

Оба приложения — оболочки вокруг сервера. Не открывается сразу везде —
значит лёг сервер, а не приложения. Смотреть журнал:

```bash
systemctl is-active truethrills truethrills-live
sudo journalctl -u truethrills -n 40 --no-pager
```

**`EACCES: permission denied` на любом файле проекта** — сервис не может
прочитать собственный код. Так случилось 23 сентября 2026: обслуживание
работает под `umask 077`, файлы создаются «только владельцу», и после смены
владельца кода на root сервису не осталось даже чтения. Лечение —
`scripts/install-operations.sh`, он выставляет права заново:

```bash
cd /opt/truethrills && sudo bash scripts/install-operations.sh && sudo systemctl restart truethrills truethrills-live
```

**`Cannot find module .../node_modules/next/dist/bin/next`** — то же самое,
просто с другим сообщением. Node не различает «файла нет» и «файл нельзя
прочитать» и в обоих случаях говорит «модуль не найден». Сначала проверь
права тем же способом, каким читает сервис, и только потом думай на
неполную установку:

```bash
sudo runuser -u truethrills -- test -x /opt/truethrills/node_modules/next/dist/bin/next && echo читается || echo НЕ-ЧИТАЕТСЯ
```

Если действительно не установлено — доставить и пересобрать:

```bash
cd /opt/truethrills && sudo npm ci --include=dev && sudo npm run build \
  && sudo bash scripts/install-operations.sh \
  && sudo systemctl restart truethrills truethrills-live
```

Проверка, что канал поднялся: `curl -fsS http://127.0.0.1:3000/api/health`.

## Копии: чего сейчас не хватает

Внешняя проверка назвала это блокером, и по скриптам она права.

`truethrills-backup.timer` снимает проверенную копию ежедневно и кладёт её в
`/var/backups/truethrills` — **на том же диске, что и сам сервер**. Это
спасает от неудачного обновления и от собственной ошибки, но не от потери
машины, диска или аккаунта. Наличие таймера не доказывает, что копия
снимается: задание останавливает приложение и воркер, поэтому во время
эфира оно может быть пропущено, а оповещение приходит только если настроен
внешний webhook мониторинга.

### Копия на свой компьютер — как делать

Два ярлыка, запускать с ПК:

- **`scripts\TrueThrills-Backup.cmd`** — снимает проверенную копию на сервере,
  шифрует её и скачивает в `Документы\TrueThrills-Backups`. Спросит пароль.
- **`scripts\TrueThrills-Restore.cmd`** — открывает скачанную копию обратно.

Про пароль честно: **он нигде не хранится и восстановлению не подлежит.**
Забыл — копия превращается в мусор. Запиши его отдельно от компьютера, на
котором лежат копии; вместе они бессмысленны.

Шифрование не для красоты: внутри архива `.env`, приватные ключи
push-подписок и адреса устройств подписчиков. Такой файл на чужом или
украденном диске — это утечка, а не резервная копия.

Открывается копия **без доустановки программ**: расшифровка идёт средствами
самой Windows, распаковка — встроенным `tar`. Openssl, Gpg4win и 7-Zip не
нужны. Это проверяется автоматически (`tests/backup-export.mjs`): формат и
параметры обоих концов обязаны сходиться, иначе прогон падает.

Рядом с копиями скрипт кладёт `LAST-BACKUP.json` с датой последней удавшейся
выгрузки. Посмотри в него, если сомневаешься, свежие ли копии: «копий нет» и
«копии есть, но им полгода» — разные беды, и на глаз они одинаковы.

### Что ещё не сделано

1. Проверка возраста последней копии с оповещением, не зависящим от этого же
   сервера. Сейчас дату видно только если открыть файл глазами.
2. Повтор пропущенного задания после эфира, а не ожидание следующих суток.
3. Учение по восстановлению на другой машине: база, звук, картинки и
   настройки, затем проверка реальных адресов медиа. Записать, сколько
   данных допустимо потерять и за сколько времени система поднимается.

**Пока ни одна копия не восстановлена на другой машине, считать, что копий
нет.** Скрипт, который отработал без ошибок, — это не доказательство.

Копия содержит `.env`, приватные ключи push-подписок и персональные данные.
Её нельзя передавать как обычный архив исходников и класть в репозиторий.
