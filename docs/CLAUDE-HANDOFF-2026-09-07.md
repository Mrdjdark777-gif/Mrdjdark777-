# True Thrills — техническая документация проекта

Дата: 7 сентября 2026. Документ для передачи другому AI-ассистенту (или разработчику),
который продолжит работу над проектом. Ниже — полное текущее состояние: что сделано,
что работает, что сломано, что нужно сделать дальше, и где что лежит.

---

## 1. Что это за проект

True Thrills — платформа автора подкастов/историй с прямыми эфирами:

- **Автор** (один человек, владелец канала) записывает и публикует подкасты, пишет
  истории, ведёт живые эфиры через свой аудиоинтерфейс (Komplete Audio 6 + ART
  TubeMP3 → SM7B).
- **Слушатели** — открытая публика, без регистрации и аккаунтов — слушают
  подкасты, читают истории, подключаются к живым эфирам, могут задонатить через
  Boosty.

Изначально проект был собран через встроенный конструктор приложений ChatGPT
("ChatGPT Sites"), что означало жёсткую привязку к инфраструктуре OpenAI:
Cloudflare Workers, база данных Cloudflare D1, хранилище Cloudflare R2, и вход
только через ChatGPT-аккаунт (в том числе для слушателей — что вообще не подходит
для публичной аудитории подкаста).

**Эта версия полностью мигрирована на самостоятельный хостинг** — обычный
Node.js-сервер на собственном VPS владельца, без зависимости от OpenAI/Cloudflare.

## 3. Сервер (текущее состояние)

- Провайдер: **Oracle Cloud (Always Free tier)**, регион Italy Northwest (Milan).
- Инстанс: `TrueThrills Server`, shape `VM.Standard.A1.Flex` (Ampere ARM), 1 OCPU / 6 GB
  RAM, Ubuntu 24.04 LTS aarch64.
- **Публичный IP: `129.152.8.230`**
- Доступ: SSH по ключу, пользователь `ubuntu`. Приватный ключ хранится у владельца
  локально на компьютере (файл `ssh-key-2026-09-06.key`). **В этот документ ключ
  намеренно не включён** — секрет, который не должен лежать в переписке с ещё
  одним внешним сервисом. Если новому ассистенту нужен доступ к серверу, владелец
  передаёт ключ отдельно, вне этого документа.
- Пароль входа в саму студию (`ADMIN_PASSWORD`) лежит на сервере в
  `/opt/truethrills/.env` (`sudo grep ADMIN_PASSWORD /opt/truethrills/.env`) —
  тоже не продублирован здесь по той же причине.
- Приложение развёрнуто в `/opt/truethrills`, запущено как systemd-сервис
  `truethrills.service` (слушает `127.0.0.1:3000`), nginx проксирует на порт 80.
- Открытые порты (Oracle Security List + ufw + iptables): 22 (SSH), 80 (HTTP),
  443 (HTTPS, пока не используется — нет сертификата).

### Как обновить/передеплоить сервер

Одна команда (безопасно запускать повторно):

```bash
curl -fsSL https://raw.githubusercontent.com/Mrdjdark777-gif/Mrdjdark777-/claude/read-link-content-h18psv/scripts/vps-setup.sh | sudo bash
```

Скрипт: ставит Node.js 22, клонирует/обновляет код из GitHub, накатывает миграции
БД, собирает (`next build`), создаёт/перезапускает systemd-сервис, настраивает
nginx и файрвол. При первом запуске генерирует `ADMIN_PASSWORD` и `SESSION_SECRET`
и один раз печатает пароль в консоль (дальше — только через `.env` на сервере).

## 4. Что уже сделано и проверено

- Полная миграция с Cloudflare Workers/D1/R2 на Node.js/SQLite/локальный диск.
- Вход: раньше — обязательный аккаунт ChatGPT и для автора, и для слушателей.
  Теперь — простой пароль для автора (`/login`), слушатели заходят без аккаунта.
- Развёрнуто на реальном VPS, приложение работает, автор успешно вошёл и закрепил
  студию за собой.
- В процессе деплоя найдены и исправлены три реальных бага (не было видно на
  локальном тестировании без прокси/HTTPS):
  1. Скрипт установки экспортировал `NODE_ENV=production` до `npm ci`, из-за чего
     npm пропускал dev-зависимости (drizzle-kit и др.) — сборка падала.
  2. Проверка источника запроса (`originCheck`, защита от CSRF) сравнивала схему
     URL (http/https), которая за nginx-прокси определяется ненадёжно — легитимные
     запросы с реального сайта отклонялись. Исправлено: сравнение теперь идёт по
     заголовку `Host`, а не по схеме.
  3. Сессионная cookie ставилась с флагом `Secure` всегда в production — такую
     cookie браузer отказывается сохранять по обычному `http://`. Из-за этого вход
     "не запоминался". Исправлено: `Secure` теперь ставится только когда запрос
     реально пришёл по HTTPS (проверка `X-Forwarded-Proto`).
- Офлайн-регрессионные тесты (`npm run test`) переписаны под новый стек и проходят
  полностью: авторизация, приватность черновиков, публикация, загрузка и
  перемотка аудио (HTTP Range), жизненный цикл эфира, изоляция токенов, удаление.

## 5. Что сейчас НЕ работает и почему

**Главная текущая блокировка: нет домена → нет HTTPS → браузер блокирует
микрофон.**

Сайт пока живёт на голом IP по `http://129.152.8.230/` без сертификата. Современные
браузеры (Chrome, Edge и др.) **отказывают в доступе к микрофону**
(`navigator.mediaDevices`) на любом сайте без HTTPS — это ограничение самого
браузера, а не баг приложения. Сейчас при попытке разрешить микрофон в студии
появляется ошибка "Аудиоустройства недоступны в этом браузере".

**Домен владелец купит завтра (8 сентября 2026 или позже)** — как только домен
будет куплен, нужно сразу выполнить шаги в разделе 6 ниже. До этого момента
проверить реальную запись через SM7B/Komplete Audio 6 невозможно.

## 6. Что нужно сделать дальше (по порядку, как только будет домен)

1. **Направить домен на сервер.** В панели регистратора добавить DNS A-запись:
   `@` (или `www`) → `129.152.8.230`. Подождать распространения DNS (обычно
   от нескольких минут до пары часов).
2. **Выпустить SSL-сертификат.** На сервере через SSH:
   ```bash
   sudo apt-get install -y certbot python3-certbot-nginx
   sudo certbot --nginx -d ВАШДОМЕН.TLD
   ```
   Certbot сам пропишет HTTPS в nginx-конфиг и настроит автопродление.
3. **Обновить `server_name` в nginx-конфиге** (`/etc/nginx/sites-available/truethrills`)
   с `_` на реальный домен — обычно это делает сам certbot автоматически.
4. **Проверить вход и запись микрофона** на `https://ВАШДОМЕН.TLD/` — с HTTPS
   `navigator.mediaDevices` должен заработать, ошибка "Аудиоустройства недоступны"
   должна исчезнуть.
5. **Обновить и пересобрать нативные клиенты**, которые сейчас всё ещё смотрят на
   старый адрес `chatgpt.site`:
   - `desktop/client.cpp` — константы `SITE` и `VIEWER` (сейчас
     `https://true-thrills.mrdjdark777.chatgpt.site`) → заменить на новый домен.
   - `android/app/src/main/java/com/truethrills/listener/MainActivity.java` —
     константа `BASE` → заменить на новый домен.
   - Пересобрать оба клиента по инструкции в `START-HERE-RU.md` (нужны Python 3 +
     Zig 0.13.0 для Windows-EXE; JDK 17 + Android SDK 35 + существующий
     signing-ключ для APK — ключ хранится у владельца отдельно, архив
     `TrueThrills-Android-Signing-Backup.zip`, не терять).
6. **Настроить кнопку доната Boosty** — в студии: Настройки → вставить ссылку на
   свою страницу Boosty.
7. **Проверить прямой эфир** живьём (реальный микрофон + второе устройство как
   слушатель). Известное ограничение: пилотный режим WebRTC до 8 слушателей,
   используется только STUN (без TURN) — в некоторых мобильных сетях/NAT
   подключение может не устанавливаться. При росте аудитории эфиров потребуется
   отдельный TURN-сервер или SFU-решение.
8. **Настроить резервное копирование.** Данные лежат в
   `/opt/truethrills/data/` (SQLite-база + аудиофайлы) на сервере. Oracle Always
   Free — бесплатно навсегда по факту, но не гарантировано юридически (были
   случаи блокировки бесплатных аккаунтов без предупреждения). Рекомендуется
   периодически копировать эту папку куда-то ещё (например, `rsync`/`scp` на
   локальный компьютер по расписанию).

## 8. Известные ограничения (честно, без приукрашивания)

- Прямой эфир — экспериментальный режим, до 8 слушателей, без TURN-сервера.
- Нет офлайн-загрузок и нативных push-уведомлений на Android (текущий APK —
  обёртка над сайтом через Chrome Custom Tabs, не полноценное нативное
  приложение).
- Донаты — просто внешняя ссылка на Boosty, приложение не обрабатывает платежи
  и не хранит данные карт.
- Максимальный размер одной аудиозаписи — 80 МБ.
- Единственный администратор — модель "один автор", built-in многопользовательский
  режим для соавторов не предусмотрен.
