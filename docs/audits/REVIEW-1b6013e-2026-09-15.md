# True Thrills — проверка и передача Claude Code

Дата: 15 сентября 2026. Основа: загруженный владельцем архив `TrueThrills-code-1b6013e.zip`, исходный SHA `1b6013e3888d82dfb39d728044f656aa519e1886`. Версия в исходниках — 0.9.2, Android versionCode 22. Изменения выполнены в отдельной локальной копии. GitHub, VPS и установленные приложения этой работой не обновлялись.

## Вердикт

Это работающий MVP с собственной серверной частью, студией Windows, Android-клиентом, публикациями, эфирами и архивом. Большая часть шести экранов уже была реализована в переданном архиве. Эта работа исправляет обнаруженные дефекты и отклонения от согласованного изображения, а не представляет весь существовавший продукт как новую разработку.

Публичную бету пока нельзя считать проверенной: нужны реальные Android/Windows, фон, блокировка экрана, FCM и контроль архива на VPS. Автоматические проверки подтверждают конкретные сценарии, но не отсутствие любых багов.

## Что сохранять

- Только бесплатный контент и добровольные донаты; никаких платных подписок и аккаунтов слушателей.
- Донат на главной и во время эфира; настоящие ссылки задаёт владелец.
- Прозрачный фирменный логотип, угольный фон, мятные акценты, существующая вибрация и ручной выбор языка.
- Существующий VPS без новых регулярных платных сервисов. ПК передаёт голос во время эфира; опубликованные записи и контент обслуживает VPS после выключения ПК.
- Рабочую схему FL Studio и нативные мосты Android/Windows. Они этой правкой не заменялись.
- Именно шесть экранов с листа владельца: S01 фотографическая главная; S02 фотографический плеер; S03 узкая типографика каталога; S04 типографический плеер с волной и «Далее»; S05 эфир с концентрическими кольцами; S06 круглая обложка архива.
- В актуальном архиве пять пунктов навигации, включая прямой вход в эфир. Это полезное более позднее изменение сохранено, хотя на исходном листе четыре пункта.

## Проверки и их границы

Среда: Linux, Node 22.14.0, FFmpeg/ffprobe, production-сборка Next, Chromium Headless Shell 141 / Playwright 1.56.1 для интерфейса. Все данные тестов временные; настоящие донаты и уведомления пользователям не отправлялись.

На исходном архиве прошли 16 наборов: `audio-file`, `device-discovery`, `studio-audio`, `api-integration`, `backup-integration`, `prune-orphans`, `live-resilience`, `home-scene`, `service-hardening`, `playback-restore`, `live-archive-integration`, `player-presentation`, `waveform`, `next-episode`, `live-stage`, `back-stack`. Это исходная проверка, её нельзя выдавать за повторный прогон всех наборов после правки.

После правок:

- `npm run build` — успешно. Сохраняется ранее документированное предупреждение Turbopack NFT для динамического пути live-stream.
- `npm run lint` — успешно.
- `node tests/live-archive-integration.mjs` — успешно: настоящий FFmpeg/HLS, порядок и повторная загрузка фрагментов, M4A и длительность, автопубликация, восстановление после исчезновения ПК, приватность и новые проверки кэша пиков.
- `node tests/worker-priority.mjs` — успешно: настоящий FFmpeg с искусственно замедленным анализом; heartbeat продолжается, архив не ждёт анализа, задача возобновляется, SIGTERM завершается без TypeError. Тест добавлен в Web checks.
- `npm run test:design` — успешно; финальный журнал `verification/review-design-final.log` в пакете. Проверен production-интерфейс с настоящим WAV: меню, Back, сохранение того же audio-элемента и продолжение звука при сворачивании, один вызов haptic, фокус, ошибка обложки, восстановление волны после pending/503, шрифты, следующий выпуск. Главная с мини-плеером на тестовом контенте помещается на 390×844 и 360×640 без перекрытия доната. Дополнительно проверены исходные сценарии размеров и студии.

Ограничения:

- `android-push-logic` не выполнился: в среде нет `javac`. Это ограничение окружения, а не подтверждённый дефект Android. Java-код этой правкой не менялся; повторить в CI с JDK 21.
- Полный `browser-integration` с AAC/HLS в настоящем Chrome в этой проверке не запускался. Headless Shell здесь использован для WAV/UI. Серверный HLS отдельно проверен FFmpeg, но это не заменяет прослушивание эфира в браузере и на телефоне.
- Не проверены реальные FCM, заблокированный телефон, системная карточка Media3, Bluetooth, звонок, энергосбережение и конкретный WebView2/аудиоинтерфейс.
- Новые APK/EXE не собирались. В этой правке изменены web/server и тесты, нативные проекты включены в полный архив без изменений. Для предыдущих нативных изменений версии 0.9.2 остаётся необходим APK соответствующей версии.
- Снимки используют тестовые обложки из `tests/fixtures/demo-covers`, вырезанные из листа владельца. Это малые демонстрационные изображения, не комплект качественных production-фотографий. Они не добавлены как настоящие публикации. Для результата как на референсе нужны исходные фотографии хорошего разрешения.
- Гарантировать отсутствие скролла на любом устройстве при любом системном размере текста нельзя. При доступности контента приоритет имеют читаемость и достижимость кнопок, а не принудительное обрезание.

## Инструкция для Claude Code

1. Прочитать этот документ, затем `docs/PROJECT-CONTEXT.md`, `docs/RELEASE-0.9.2-RU.md`, `docs/OPERATIONS-0.9-RU.md` и требования владельца. Ранние сведения о текущем SHA сервера — исторический снимок, их надо проверить перед выкладкой.
2. Сопоставить актуальную ветку с исходным SHA `1b6013e3888d82dfb39d728044f656aa519e1886`. Если после него были изменения, не перезаписывать проект целиком: перенести исправления из `review.patch` с разрешением конфликтов и сохранением новых функций.
3. Для чистой основы применить патч из корня репозитория (путь заменить на фактический):

```sh
git apply --check /path/to/review.patch
git apply /path/to/review.patch
```

4. Альтернатива для просмотра: папка `source/` содержит весь обновлённый исходный код, в том числе Android, Windows, сервер, миграции и документацию. Не заменять ею живые данные, `.env`, ключи Firebase или подписи APK.
5. В среде Node 22, FFmpeg и JDK 21 выполнить установку по lockfile, lint/build и проверки Web checks. Изменённые проверки запускаются так:

```sh
npm ci --include=dev
npm run lint
npm run build
npm run test:live
node tests/worker-priority.mjs
node tests/android-push-logic.mjs
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install chrome
npm run test:design
npm run test:browser
```

Команды показаны для Linux/CI. Нативную Windows-студию и Android собирать существующими workflow проекта. Не запускать обновление сервера лишь потому, что локальные тесты прошли.

6. Перед ограниченной бетой выполнить аппаратную приёмку ниже и записать фактические результаты, устройства, версии ОС и APK. Затем сверить ветку, сделать резервную копию, применить существующую процедуру безопасного обновления и проверить сервер после выкладки. Самовольная настройка платных услуг не требуется.

## Аппаратная приёмка перед бетой

- Android: начать подкаст, свернуть приложение, заблокировать экран на 30–60 минут. Проверить системную карточку, паузу/продолжение/перемотку и сохранение позиции при возврате. Повторить с прямым эфиром и записью эфира.
- Начать эфир при свёрнутом/заблокированном приложении слушателя: получить одно корректное уведомление; одно нажатие открывает нужный эфир. Отдельно проверить запрет уведомлений и завершившийся эфир.
- Проверить Wi-Fi → мобильная сеть → потеря сети → восстановление. Интерфейс не должен называть буферизацию играющим звуком. Звонок и отключение наушников — проверка паузы/audio focus, а не новые функции звонков.
- Проверить видео каждого поддержанного внешнего поставщика отдельно. Наличие аудиоплеера Media3 само по себе не доказывает фоновое воспроизведение внешнего embed-видео.
- Windows: вход из FL Studio, голос + музыка, наушники, начало/остановка эфира и записи; нет двойного мониторинга и эха.
- Завершить эфир, дождаться архива на VPS, выключить ПК, открыть архив и подкаст на телефоне, перемотать к концу. При внезапном исчезновении ПК проверить сохранение именно принятых сервером данных.
- Проверить донат с реальным URL на главной и в эфире; возврат в приложение не должен ломать плеер.
- Проверить русский, итальянский, украинский, румынский, системный крупный текст, 360 px экран и нативные safe areas.
- Проверить резервную копию восстановлением в отдельную папку/тестовую среду, не поверх работающего VPS.

## Состав пакета

- `source/` — полный обновлённый проект без зависимостей, сборок, локальной БД и секретов.
- `review.patch` — изменения относительно переданного архива, включая новые тесты и этот документ.
- `verification/` — журналы исходных и повторных проверок; `review-android-push-logic.log` содержит ожидаемое ограничение среды.
- `screenshots/` — снимки приложения с временным демонстрационным контентом.
- `reference/` — предоставленный владельцем лист шести экранов.
