## Версии и фактическая готовность

До текущих изменений: web/Windows 0.5.0, Android 0.7.0 code 9. Ветка Codex: web/Windows/Android 0.8.0, Android code 10. Для APK используется прежний ключ из GitHub Secrets; не генерировать новый.

Android Media3 воспроизводит подкасты отдельной службой, WebMessageListener ограничен первым фреймом точного origin. Подписанная сборка + Android lint пройдены в Actions. Нужны физические тесты телефона: блокировка, аудиофокус, наушники, таймер, push. Прямой эфир остаётся WebRTC/WebView; фоновое воспроизведение эфира ещё не подтверждено и требует отдельного решения при обрывах.

Веб-часть получила нативный плеер, скорость/таймер/позицию, главную с продолжением и последней публикацией, размер/позицию чтения, обложки по HTTPS. Сервер: FCM TTL, атомарная ротация, лимит входа, health, опциональные TURN credentials. Миграция 0005 обязательна перед запуском нового кода.

Подготовлены проверяемые backup/restore, локальный мониторинг диска/HTTPS/возраста копии и systemd timers. На VPS они не запускались. Копия на том же VPS не заменяет отдельную копию на ПК. Монитор пока записывает результат и journal; внешнего аварийного оповещения нет.

Лимиты пилота: 8 слушателей, 100 push-устройств, 80 МБ аудио. TURN не настроен автоматически на VPS. Платный доступ/аккаунты слушателей/проверка платежей отсутствуют; есть внешняя ссылка поддержки. Эти границы нельзя выдавать за завершённые функции.

## Следующие проверки и этапы

1. Применить готовое обновление на сервере с резервной копией и миграцией; установить APK и EXE из успешной сборки точного коммита.
2. Пройти матрицу устройства из RELEASE-0.8-RU.md. Исправить конкретные результаты. Для фона live при необходимости перенести WebRTC в нативную службу.
3. Включить backup/monitor timers и сохранить приватную копию вне VPS. Проверить восстановление отдельно от рабочей базы.
4. Настроить coturn на существующем VPS и проверить relay между разными сетями. Сохранить лимиты пилота.
5. Провести небольшой запуск, проверить кнопку поддержки. После выбора провайдера/модели пользователя реализовывать платный доступ через подтверждённые платежи, а не по факту перехода по ссылке.
