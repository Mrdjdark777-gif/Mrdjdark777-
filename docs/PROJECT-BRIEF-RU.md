# True Thrills — полное описание проекта

Документ для человека или ИИ, который видит проект впервые. Всё в нём проверено
по коду на 13 сентября 2026 года. Если что-то расходится с кодом — прав код.

---

## 1. Что это

Собственная платформа автора канала True Thrills: подкасты, истории, ссылки на
видео и прямые аудиоэфиры. Не сервис для многих авторов — один владелец, один
канал, остальные только слушают.

Правила, заданные владельцем и не подлежащие пересмотру без его слова:

- **Весь контент бесплатный.** Платного доступа нет и не планируется. Деньги —
  только добровольные донаты (Boosty и PayPal), кнопка ведёт наружу.
- **Никаких аккаунтов у слушателей.** Регистрации нет. Прогресс прослушивания,
  скрытые карточки и подписка на уведомления живут в самом устройстве.
- **Свой сервер, без чужих облаков.** Хранение файлов, база и раздача — на
  собственном VPS. Ничего не уходит в сторонние сервисы, кроме Firebase для
  доставки push на Android.
- **Бюджет.** Используется уже оплаченный VPS, новых регулярных трат нет.

## 2. Из чего состоит

| Часть | Технологии | Где живёт | Для кого |
|---|---|---|---|
| Сервер и веб-интерфейс | Next.js 16.2.12, React 19.2.6, TypeScript, Tailwind 4 | Ubuntu 24.04 на ARM VPS, `/opt/truethrills` | всех |
| Приложение-слушатель | Java, WebView + Media3/ExoPlayer 1.5.1, FCM | Android, minSdk 26, targetSdk 35 | аудитории |
| Студия автора | C++ / WebView2 | Windows | владельцу |
| Воркер эфира | Node + FFmpeg, отдельный процесс systemd | тот же VPS | системе |

Оба нативных клиента — это **оболочки вокруг того же веб-интерфейса**. Вся
вёрстка и логика экранов одна, на сервере. Нативная часть добавляет то, чего
браузер не умеет: фоновое воспроизведение, уведомления, захват звука с ПК.

Отсюда практическое следствие: **изменение интерфейса не требует новой сборки
приложения.** APK пересобирают только когда меняется нативный код (плеер,
уведомления, мост). Сейчас versionCode 20, versionName 0.9.0.

## 3. Сервер

### Стек

Next.js (App Router, Turbopack) → SQLite через drizzle-orm 0.45.2 и
better-sqlite3. Файл базы и хранилище лежат на диске, путь задаётся в `.env`.
Снаружи nginx с сертификатом Let's Encrypt проксирует на localhost:3000.

### Маршруты API (`app/api/`)

| Маршрут | Что делает |
|---|---|
| `auth` | вход владельца по паролю, сессионная cookie |
| `library` | список публикаций, создание и правка, настройки канала, ссылки на донаты и площадки |
| `audio` | потоковая загрузка аудио, отдача с поддержкой Range |
| `cover` | загрузка и отдача обложек выпусков, эфиров и оформления канала |
| `live` | запуск и остановка эфира, статус, сердцебиение, учёт слушателей |
| `live-stream` | приём кусков звука от студии, раздача HLS-плейлиста и сегментов |
| `notifications` | подписка на уведомления, настройки категорий |
| `health` | проверка живости для мониторинга |
| `ice` | параметры TURN (остаток прежнего WebRTC-пути, эфир его не использует) |

### Таблицы (`db/schema.ts`, 9 миграций в `drizzle/`)

- `posts` — публикации: `kind` (podcast / video / story), заголовок, описание,
  текст, `audio_key`, `video_url`, обложка, длительность, `published`.
- `broadcasts` — эфиры: название, владелец, сердцебиение, активен ли, обложка.
- `live_recordings` — запись эфира: состояние (`receiving` → `closing` →
  `processing` → `ready` / `failed`), номер следующего куска, объём, плейлист,
  id созданного выпуска.
- `peers` — подключённые слушатели эфира, по сердцебиению.
- `push_subscriptions`, `push_events`, `push_outbox` — устройства, события и
  очередь доставки уведомлений.
- `settings` — пары ключ-значение: владелец, ссылки на донаты, площадки,
  оформление канала.
- `rate_limits` — счётчики попыток (защита входа).

### Защита

Вход — пароль владельца из `.env`, дальше подписанная cookie
(`lib/auth.ts`). Каждый изменяющий запрос проходит `requireOwner`, который
проверяет и сессию, и совпадение Origin (`lib/server.ts`). Черновики
недоступны никому, кроме владельца. Ключи файлов не угадываются: UUID.

## 4. Прямой эфир — весь путь звука

Это самая сложная часть системы, и устроена она намеренно так, а не иначе.

1. **Студия на ПК** берёт звук с микшера, режет на куски по 2 секунды
   (WebM/Opus) и отправляет их по HTTPS в `live-stream` с порядковым номером и
   хешем. Повторная отправка того же куска идемпотентна: при обрыве сети
   студия просто шлёт заново.
2. **Сервер** складывает куски на диск и обновляет `live_recordings`.
3. **Воркер** (`scripts/live-worker.mjs`, отдельный systemd-процесс) поднимает
   FFmpeg, склеивает куски в HLS: сегменты `seg-NNNNNN.ts` и плейлист.
4. **Слушатель** играет HLS через hls.js в браузере или через Media3 на
   Android. Задержка несколько секунд — это плата за то, что звук идёт через
   сервер, а не напрямую.
5. **После эфира** воркер перекодирует запись целиком в M4A (AAC 192 кбит/с),
   создаёт выпуск-подкаст, переносит на него обложку эфира и публикует.
6. **Через 30 минут** каталог эфира удаляется. Пауза намеренная: слушатель,
   подключившийся в последнюю минуту, дотягивает остаток по плейлисту.

Почему через сервер, а не напрямую от ПК каждому (прежний путь был на WebRTC):
ПК автора не тянет раздачу многим, а главное — при таком пути запись эфира
зависела бы от того, доживёт ли браузер до конца. Сейчас ПК нужен **только как
источник звука**; всё остальное доживает без него.

Ограничения, заданные в коде: до 8 часов или 1 ГиБ входящего звука на эфир, до
50 одновременных слушателей, отказ при нехватке места на диске.

## 5. Подкасты, видео, истории

- **Подкаст** — загруженный аудиофайл либо автоматически созданная запись
  эфира. Отдаётся с поддержкой Range, поэтому перемотка работает без
  докачивания целиком. На Android играет нативный Media3 в фоне, с
  уведомлением и значком канала.
- **Видео** — не хранится у нас. Это внешняя ссылка (YouTube, Rutube, VK,
  TikTok), которую `lib/video.ts` разбирает и превращает в безопасный embed:
  без cookie-домена, без аннотаций, вертикальные Shorts в вертикальной рамке.
- **История** — текст в базе, читалка с настройкой размера шрифта и
  сохранением места чтения.

Прогресс прослушивания хранится **в устройстве** (`lib/listening-progress.ts`),
на сервер не уходит: аккаунтов нет, знать, кто что слушал, не нужно и не
хочется.

## 6. Уведомления

Два пути в одном интерфейсе:

- **Браузер** — Web Push по стандарту, ключи VAPID генерируются на сервере.
- **Android** — Firebase Cloud Messaging, потому что Web Push в WebView не
  работает надёжно.

Подписка анонимная: устройство получает случайный токен, по нему и управляет
своими настройками. Категории раздельные: начало эфира, новый подкаст или
видео, новая история. Очередь `push_outbox` с повторами и сроком годности —
уведомление о начавшемся эфире через час уже бессмысленно и не доставляется.

## 7. Языки

Четыре: русский, итальянский, украинский, румынский. Выбор автоматический по
языку телефона, ручного переключателя нет намеренно.

Устройство: `lib/i18n/ru.ts` — источник истины, около 400 строк. Остальные
словари типизированы как `Record<keyof typeof ru, string>`, поэтому **и
пропущенный, и лишний ключ роняют сборку**. Забыть перевод невозможно.

Сердечко доната в шапке ведёт на PayPal при итальянском языке телефона и на
Boosty при остальных: PayPal не работает внутри России, Boosty за её пределами
почти никому не знаком. В блоке поддержки видны оба.

## 8. Хранилище, бэкапы, обслуживание

Файлы лежат на диске сервера (`data/storage`), эфиры отдельно (`data/live`).

**Бэкап** (`scripts/backup-data.mjs`) снимает базу через штатный SQLite backup
API — не копированием файла, иначе можно получить рассыпающийся снимок, —
плюс всё хранилище, `.env` и ключ Firebase. Каждая копия проверяется
(`verify-backup.mjs`): считается, сколько выпусков со звуком в живой базе, и
копия с меньшим числом отвергается. Ежедневный запуск по таймеру systemd,
хранятся последние пять, остальные удаляются — но только после того, как новая
копия записана и проверена.

**Копия вне сервера** обязательна: `scripts/export-backup.sh` собирает архив,
владелец забирает его на ПК через scp и сверяет sha256. Пять копий на том же
диске не спасают от потери самого диска.

**Уборка** (`scripts/server-cleanup.sh`) — отчёт по умолчанию, удаление только
с `--apply`: остатки прерванных обновлений, каталоги завершённых эфиров, кэш
npm, старые журналы, лишние бэкапы и хвосты в базе (мёртвые записи эфиров и
файлы, на которые никто не ссылается).

**Обновление** (`scripts/update-safe.sh`) — единственный правильный способ:
проверяет, что не идёт эфир, останавливает сервисы, снимает бэкап, тянет
ветку, ставит зависимости, применяет миграции, собирает, запускает обратно. При
ошибке останавливается и сообщает, с какой копии восстанавливаться.

## 9. Репозиторий и сборка

Одна рабочая ветка — `truethrills-app`, она же основная. Вторая ветка,
`blender-helper-bot`, к этому проекту отношения не имеет.

```
app/          экраны и API
components/   компоненты интерфейса (studio/ — свои, ui/ — 7 из shadcn)
hooks/        useCapture, useLive, useNotifications
lib/          серверные помощники, i18n, работа со звуком и ссылками
db/           схема и подключение
scripts/      всё серверное обслуживание
tests/        десять наборов проверок
android/      приложение-слушатель
desktop/      студия автора
```

Три сборки в GitHub Actions:

- **Web checks** — lint, сборка, синтаксис серверных и PowerShell-скриптов и
  все десять тестов, включая браузерный на настоящем Chrome и проверку
  решений об уведомлениях Android на настоящей JVM.
- **Build Android APK** и **Build Windows EXE** — запускаются только когда
  менялись `android/` или `desktop/`.

Тесты работают с настоящими вещами, а не с заглушками: `live-archive` гоняет
настоящий FFmpeg и проверяет весь путь эфира до опубликованного выпуска,
`browser-integration` открывает реальный браузер, `backup-integration` ломает
копию разными способами и убеждается, что проверка это ловит.

## 10. Что стоит знать, прежде чем что-то менять

- **Интерфейс меняется без пересборки приложения.** Обновил сервер — увидел
  изменения. Исключение только нативная часть.
- **Дизайн сначала показывают, потом кодят.** Владелец отверг одну переделку
  главного экрана целиком; договорённость — сперва макет, потом код.
- **Не выдумывать данные.** Бегущая полоса, которая «показывала» то, чего нет,
  была снята по прямому замечанию владельца. Лучше не показать ничего, чем
  нарисовать правдоподобное.
- **Прежде чем удалять — посмотреть.** Все скрипты уборки по умолчанию только
  отчитываются.
- **Нельзя объявлять проверенным то, что прошло только в CI.** Реальные
  телефон, ПК и сервер — отдельная проверка.

### Известные шероховатости

- Сборка пишет одно предупреждение Turbopack «Encountered unexpected file in
  NFT list» с трассой через `app/api/live-stream/route.ts`: трассировщик не
  может статически оценить путь к файлам эфира. На работу не влияет,
  испробованные способы (`turbopackIgnore`, вынос склейки пути, синхронное
  чтение) его не гасят.
- Эфир требует включённого ПК как источника звука. Непереданные данные при
  пропадании ПК восстановить нельзя — сохраняется принятая часть.
- Аудитории пока нет: один опубликованный выпуск. Все решения про нагрузку
  приняты с запасом, но на живых людях не проверялись.
