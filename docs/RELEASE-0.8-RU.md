# True Thrills 0.8 — подготовка к тестовому запуску

Дата: 9 сентября 2026. Исходная версия: `953e92d`, ветка Claude `claude/read-link-content-h18psv`. Изменения Codex: `codex/stabilize-0.8`.

Это версия для проверки перед выпуском. Коммит в GitHub, готовый установщик и установленное обновление сервера — разные состояния. Доступа к Oracle VPS, Windows и физическому Android в этой работе нет; выполнение серверных команд и проверка на телефоне не подтверждены.

## Что изменилось

- Android 0.8.0 / versionCode 10: отдельный Media3 MediaSessionService для подкастов. Плеер принадлежит службе, а не странице WebView. Команды на экране блокировки, обработка потери аудиофокуса и отключения наушников обеспечиваются Media3. Положение, скорость и таймер сна хранятся на телефоне.
- Безопасный мост `TrueThrillsNative` использует WebMessageListener: только HTTPS `truethrills.com`, только главный фрейм. Видео во вложенном фрейме не получает нативные возможности. Для устаревшего WebView новый мост недоступен: нужно обновить Android System WebView. Веб-часть сохраняет совместимость со старым APK.
- Подкасты: сохранение позиции, скорость 0.75–2×, таймер сна 15/30/60 минут, возобновление с главного экрана. На старом APK/в браузере воспроизведение остаётся HTML Audio; нативные гарантии к нему не относятся.
- Главная слушателя показывает последнюю публикацию и незавершённый подкаст. Истории сохраняют положение чтения и размер текста. Автор может задать HTTPS-ссылку на обложку; изображение загружается с указанного сервера без передачи Referer.
- Push: статус учитывает разрешение Android и канал уведомлений; есть переход в системные настройки. Запрос разрешения происходит по кнопке включения. Отключение немедленно заглушает уведомления локально, а при сбое сети сохраняет токен управления для повторной попытки.
- Срок жизни FCM соответствует сроку события в очереди. Android отбрасывает просроченные сообщения. Ротация FCM переносит подписку с подтверждением владения; прежняя удаляется в транзакции. Язык и категории сохраняются.
- На API 26–32 сетевой клиент читает ответ через буфер вместо неподдерживаемого `readAllBytes`. Ответы HTTP с ошибкой не выдаются за успех. Веб-запросы к нативному мосту имеют тайм-аут.
- Вход автора: максимум 10 попыток за 10 минут, состояние в SQLite. По IP работает только при `TRUST_PROXY=true` и nginx, который перезаписывает `X-Real-IP`; Next должен слушать только localhost. Без доверенного прокси действует общий лимит.
- `/api/health` проверяет доступность SQLite и свободный диск. Только автор получает детали о push/TURN/прокси. Проверка конфигурации Firebase не доказывает доставку push.
- `/api/ice` выдаёт краткоживущие TURN-пароли при активном эфире либо автору. Секрет остаётся на сервере. Если TURN не настроен, используется прежний STUN.
- Windows 0.8.0: исправлен текст входа в окне «О программе», добавлена автоматическая сборка EXE с проверкой ресурсов и содержимого установщика.

## Принципиальное ограничение эфира

Media3 в этой версии обслуживает **записанные подкасты**. Прямой эфир остаётся WebRTC внутри WebView. Нельзя объявлять фоновый эфир исправленным только потому, что подкаст играет при блокировке. Для эфира требуется отдельный тест минимум 30 минут на реальном телефоне; при обрыве следующий этап — нативный WebRTC-приёмник/служба с сохранением сигналинга и media session.

Сохраняются пределы пилота: 8 слушателей одновременно, 100 push-подписок, 80 МБ на аудиофайл. TURN помогает соединению через NAT, но не превращает схему «автор → каждый слушатель» в массовое вещание.

## Проверки

В текущей рабочей среде пройдены TypeScript, API regression (включая ограничение входа, TTL, смену токена и защиту чужой подписки), проверка и отдельное восстановление тестовой резервной копии. ESLint: 0 ошибок, остаются предупреждения существующей кодовой базы. Android APK подписан прежним ключом в GitHub Actions, `assembleRelease` и `lintRelease` прошли.

Браузерный тест на ширине 390 px прошёл: длительность и прогресс, скорость, восстановление размера/позиции истории, нативные команды без второго HTML Audio. Окно чтения получило непрозрачный фон. Проверки веб-интерфейса выполняются отдельно от Android: они не доказывают поведение энергосбережения телефона, FCM или реального аудиоинтерфейса. Результат последней CI-сборки смотреть по конкретному коммиту в GitHub Actions.

## Установка и приёмка

1. Сначала обновить сервер и применить миграцию `0005_eminent_king_bedlam.sql` через Drizzle (добавляются `cover_url` и `rate_limits`). Инструкция: `OPERATIONS-0.8-RU.md`. Без неё веб-часть 0.8 не готова к работе.
2. Установить APK поверх существующего приложения. Не удалять приложение: это уничтожит локальные настройки и позицию. Ключ подписи должен остаться прежним.
3. Запустить подкаст, перейти к середине, выбрать скорость, заблокировать телефон на 30 минут. Проверить паузу/продолжение с экрана блокировки, Bluetooth/проводные наушники, входящий звонок и возвращение в приложение. Таймер сна должен остановить звук при заблокированном экране.
4. Включить push, нажать проверку, заблокировать телефон. Опубликовать тестовый выпуск и запустить эфир с ПК. Одно нажатие по уведомлению должно открыть нужный материал. Отключить системное разрешение и убедиться, что приложение показывает блокировку.
5. Без интернета выключить push: уведомления локально заглушаются; после восстановления интернета повторить отключение. Отдельно проверить обычное закрытие приложения и принудительную остановку Android: после Force stop доставка возобновляется только после запуска приложения.
6. Эфир проверить отдельно на Wi-Fi и мобильной сети, затем 30 минут с блокировкой. Записать модель телефона, версию Android, длительность и результат. Не отмечать тест пройденным заранее.
7. Установить Windows EXE, проверить пароль автора, иконку, запись с CABLE Output и живой эфир. Звуковая схема FL Studio описана ниже.

## FL Studio и музыка

SM7B → ART TubeMP Studio V3 → Komplete Audio 6 MK2 → Windows. В FL Studio обработка голоса находится на отдельном Mixer Insert. Музыка — на другом Insert; sidechain с голоса управляет компрессором музыки (например, Fruity Limiter в COMP), чтобы при речи музыка приглушалась. Общий Master не должен клиппировать.

Рабочая схема владельца: FL Studio ASIO input Komplete, output CABLE Input; в True Thrills — CABLE Output и режим FL Studio/стерео. Master Stereo separation в FL Studio по центру. Не сводить готовый стереомикс в один канал приложения.

Наушники подключены к Komplete. Ручка INPUT/HOST — к HOST. Windows «Прослушивать CABLE Output» направлено на Komplete 1/2. Следить, чтобы сигнал мониторинга не возвращался на вход FL и не образовывал петлю. Если в True Thrills уже поступает готовый обработанный микс, повторная компрессия/шумоподавление приложения не нужны.

## Деньги и дальнейший план

Сейчас заработок — внешняя ссылка поддержки; она видна автору и слушателям. Переход по ссылке не означает проверенную оплату, донат не открывает закрытый материал автоматически.

Порядок до публичного запуска: проверка телефона → проверенная резервная копия вне VPS → TURN и тест двух сетей → небольшой пилот в пределах 8 слушателей → исправления по результатам. Масштабирование и платный доступ идут после этого.

Для платного доступа ещё нужны выбор провайдера, цена/срок, модель идентификации слушателя, подтверждение платежа на сервере, идемпотентные webhook, отзыв доступа при возврате и тестовый режим оплаты. Без этих решений нельзя безопасно включить реальные списания. Платные сервисы, подписки и покупки в этой работе не подключались.
