## Что находится по ссылке

ECC, ранее Everything Claude Code, — открытый набор инструкций и инструментов для coding assistants. Агенты задают специализированные роли, skills описывают рабочие процессы, команды вызывают их, hooks выполняют код при событиях, а MCP подключает внешние инструменты. Это не новые модели и не отдельные постоянно работающие сотрудники.

Набор большой и охватывает много языков, не нужных этому приложению. Его сильная сторона — повторяемая проверка: планирование, ревью, безопасность, воспроизведение ошибки, проверка результата. Он не превращает непроверенный ответ в доказательство, не гарантирует отсутствие багов и не заменяет проверку на настоящем телефоне.

Открытая часть имеет MIT-лицензию. Отдельный ECC Pro — коммерческое предложение; для предложенной настройки он не требуется. Лимиты и оплата Claude остаются: каждый дополнительный агент расходует ресурсы текущего тарифного плана или API. Поэтому запускать всех сразу не стоит.

## Что подготовлено для твоего приложения

В репозиторий добавлены шесть собственных адаптированных ролей, вдохновлённых организацией ECC, и одна project skill. Это выборочная интеграция подхода ECC, а не установка всего upstream-плагина.

| Роль | Для чего |
| --- | --- |
| tt-ecc-planner | План изменений и критерии готовности |
| tt-ecc-reviewer | Ошибки и регрессии по реальному diff |
| tt-ecc-security | Авторизация, загрузки, пути, границы доступа |
| tt-ecc-build | Минимальные исправления сборки и TypeScript |
| tt-ecc-tests | Существующие проверки и воспроизводимые сценарии |
| tt-ecc-data | SQLite, архивы, резервирование, счётчики |

Определения лежат в .claude/agents/. Процесс — .claude/skills/tt-ecc-workflow/SKILL.md.
Существующий CLAUDE.md не заменён. Помощники учитывают его правила, текущую структуру папок и Node 22, вместо универсальных рецептов.

Это особенно полезно для читалки, переключения полноэкранного режима, сохранения позиции аудио, повторного подключения к эфиру, сохранения архивов и достоверности счётчиков. Юридический агент не добавлен: сертификат законности по промпту получить невозможно.

## Как работать при выключенном ПК

Нужен именно Claude Code в облаке: https://claude.ai/code или облачный Code-сеанс в приложении Claude. Облачная задача выполняется на инфраструктуре Anthropic. Windows можно выключить после запуска облачной задачи. Это отличается от Remote Control, который управляет локальным процессом и зависит от включённого ПК.

Project agents и skills находятся в Git, поэтому доступны сеансам, которые загрузили нужную ветку репозитория. Они не становятся автоматически глобальными для всех репозиториев и обычных чатов Claude.

1. Открой PR, созданный для этой настройки, проверь состав файлов и слей его в design/six-screens. Можно сначала проверить непосредственно ветку PR.
2. В Claude Code выбери репозиторий Mrdjdark777-gif/Mrdjdark777- и ветку с этими файлами.
3. Создай новый облачный сеанс, чтобы конфигурация была загружена с самого начала.
4. Отправь текст:

> Прочитай CLAUDE.md и docs/owner/ECC-SETUP-RU.md. Проверь наличие tt-ecc-workflow и шести tt-ecc-агентов. Назови найденные роли. Для работы над True Thrills применяй этот процесс и вызывай только нужных специалистов. Не выдавай наличие файлов за успешную runtime-проверку.

Затем обычная задача:

> Применяй tt-ecc-workflow. Проверь сохранение текста текущей страницы при переходе читалки в полноэкранный режим. Исправь подтверждённые ошибки, сохрани остальные изменения и сообщи реальные результаты проверок.

Если skill-команды доступны в конкретном интерфейсе, можно вызвать /tt-ecc-workflow. Если нет — достаточно назвать skill в тексте. Для целевого ревью попроси использовать tt-ecc-reviewer.

Сеанс не является круглосуточным сервером: он имеет лимиты и срок жизни. Доступность инструкций при выключенном ПК не означает, что помощники постоянно работают без задачи. Для другого репозитория эти файлы нужно перенести отдельно.

## Почему не установлен весь плагин в облако

Официальная документация сообщает, что /plugin не доступен в облачных сеансах и плагины из .claude/settings.json там не загружаются. Поэтому обещать перенос Windows-плагина в облако было бы неверно.

Skills можно также включать на уровне аккаунта claude.ai для нескольких проектов. Эта настройка выполняется в разделе skills/Customize аккаунта. В данный пакет входят repo-local skills; настройки аккаунта здесь не изменялись. Аккаунтный skill не равнозначен установке всех ECC agents, hooks и MCP.

## Если позже понадобится полный ECC на Windows

Это отдельная необязательная установка в локальном Claude Code. В его интерактивном интерфейсе:

```text
/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc
```

Сначала проверь текущую upstream-документацию и выбранную версию: установка marketplace может получить более новый релиз. Не совмещай эту установку с полной ручной копией ECC для того же окружения: возможны дубли команд и hooks.
Проверяй /plugin list. Установленное только на ПК не доступно облачному сеансу автоматически.
Альтернативный upstream wizard: npx ecc-universal@2.2.3 setup. Это запуск стороннего установщика; здесь он не выполнялся.

Hooks выполняют реальный код. MCP может получать доступ к браузеру и другим ресурсам. Наш набор не добавляет hooks, не ослабляет permissions, не подключает MCP, не требует API-ключей и не покупает дополнительные сервисы. Полный аудит безопасности всего ECC не выполнен; прочитаны README, метаданные плагина, выбранные агенты/skill и часть конфигурации hooks.

## Проверки и границы результата

Проверены синтаксис frontmatter, уникальность имён, состав файлов и отсутствие исполняемых hooks/settings/MCP в подготовленном наборе.
Runtime-запуск этих ролей в аккаунте владельца не выполнялся: доступа к управлению аккаунтом Claude нет.
Продуктовый код и зависимости приложения не меняются. Сборка приложения для изменения Markdown-инструкций не запускалась.
При первом облачном запуске требуется подтвердить обнаружение ролей и успешный вызов хотя бы одного специалиста.
