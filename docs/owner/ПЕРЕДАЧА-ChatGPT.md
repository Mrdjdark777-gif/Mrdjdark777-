# Передача работы: как продолжать True Thrills с другим помощником

Этот файл написан для помощника, который продолжит работу вместо Claude Code, и
для владельца — чтобы он знал, чего от помощника требовать.

Ветка, на которой идёт работа: **`design/six-screens`**. Номер текущего коммита
здесь намеренно не записан — он меняется с каждой правкой. Посмотреть его можно
в GitHub наверху страницы ветки или внизу главной в самом приложении, там стоит
штамп сборки.

---

## 1. Главное, что меняется

Claude Code работал **внутри** проекта: сам читал файлы, сам правил код, сам
прогонял проверки, сам коммитил и отправлял в GitHub. Помощник в чате так не
может — у него нет ни доступа к репозиторию, ни ключа к серверу, ни возможности
запустить проверки.

Поэтому цепочка становится другой, и посредник в ней — владелец:

```
помощник отдаёт готовые файлы
        ↓
владелец кладёт их в репозиторий (GitHub)
        ↓
владелец запускает обновление сервера
        ↓
владелец смотрит на телефоне и рассказывает, что вышло
```

Из этого следует главное требование к помощнику:

> **Отдавать файл целиком, а не куском.** «Замени в этом месте вот на это» здесь
> не работает: владелец не редактирует код руками. Нужен весь файл от первой
> строки до последней, с именем и путём, например `lib/page-curl.ts`.

Второе требование:

> **Не выдавать непроверенное за проверенное.** Помощник не может запустить ни
> сборку, ни проверки. Значит, он обязан писать прямо: «это не проверено, проверь
> на телефоне». Фразы «теперь всё работает» без прогона — неправда.

## 4. Правила, по которым велась работа

Они не формальность — каждое написано после конкретной поломки.

**Спрашивать до правки, а не отчитываться после.** Если непонятно, что оставить,
а что заменить, — спросить владельца до изменения, а не ставить перед фактом.

**Проверка, которая ничего не находит, — не проверка.** Каждая новая проверка
прогоняется мутацией: сломать код нарочно, убедиться, что прогон называет
поломку словами, вернуть обратно. За время работы несколько проверок оказались
слепыми именно так — они «проходили» и на исправном коде, и на сломанном.

**Не выдавать непроверенное за проверенное.** Не прогнал — так и сказать.

**Ничего из этого не выкладывать никуда и никогда:** ключ SSH, серверный `.env`,
`firebase-service-account.json`, ключ подписи APK. Ни в архив, ни в переписку, ни
помощнику. Помощнику они не нужны: он не ходит на сервер.

## 5. Как теперь выкладывать правки

### Шаг 1. Получить файлы от помощника

Целиком, с путями. Сохранить их в распакованную папку проекта поверх старых.

### Шаг 2. Отправить в GitHub

Репозиторий: `Mrdjdark777-gif/Mrdjdark777-`, ветка **`design/six-screens`**.
Сервер обновляется именно с неё.

**Путь А — через сайт GitHub, ничего ставить не нужно.** Подходит, когда файлов
немного.

1. Открыть github.com, репозиторий, переключиться на ветку `design/six-screens`.
2. Зайти в нужную папку (например `lib`).
3. «Add file» → «Upload files», перетащить файл, он заменит старый.
4. Внизу написать, что изменено, и нажать «Commit changes».

**Путь Б — через Git на компьютере.** Удобнее, когда файлов много. Поставить
Git for Windows один раз, дальше в PowerShell из папки проекта:

```powershell
git add -A
git commit -m "что изменено"
git push origin design/six-screens
```

### Шаг 3. Обновить сервер

Из папки проекта в PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
Get-ChildItem -Recurse -Filter *.ps1 | Unblock-File
.\tools\windows\TrueThrills-Server.ps1 -Action Update -KeyPath "D:\True Thrills\Private SSH - Key\ssh-key-2026-09-06.key"
```

Идёт несколько минут. В конце обязаны быть **обе** строки:

```
Выложен коммит: <код> (design/six-screens)
Сборка совпадает с кодом: <код>
```

Второй строки нет — обновление не доехало, смотреть, на чём встало.

### Шаг 4. Убедиться, что на телефоне именно новый код

Настройки → Приложения → True Thrills → Память → **Очистить кэш**
(«Очистить данные» не трогать), открыть заново. Внизу главной, рядом со строкой
о правах, стоит короткий код сборки — он обязан совпасть с тем, что напечатало
обновление.

Этот штамп появился не просто так: трижды подряд обновление проходило
«успешно», а на телефоне оставалось прежнее приложение, и выяснять это
приходилось кругом переписки.

Проверить сервер можно и так: открыть в браузере
`https://truethrills.com/api/health` — ответ отдаётся без кэширования и всегда
показывает то, что реально работает.

### Шаг 5. Если правился нативный код — пересобрать APK

Обновление сервера меняет сайт внутри приложения, но не саму оболочку. Всё, что
лежит в `android/` — плеер, уведомления, мост между сайтом и телефоном
(`android/app/src/main/java/com/truethrills/listener/NativeBridge.java`) — живёт
в APK, и пока APK не пересобран, новый мост телефону неизвестен. Признак такой
поломки: сайт зовёт метод моста, приложение молчит, а в браузере то же самое
работает.

Собирать APK руками не нужно и нельзя: ключ подписи лежит не на компьютере, а в
секретах GitHub (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`GOOGLE_SERVICES_JSON_BASE64`). Сборку делает GitHub:

1. GitHub → репозиторий → **Actions** → слева **Build Android APK**.
2. Кнопка **Run workflow**, в списке ветку **`design/six-screens`**, запустить.
   Сама она запускается при правках `android/` в этой ветке, но без выкладки
   на сайт; выложить — только руками, с отметкой publish.
3. Несколько минут. Когда прогон позеленеет — открыть его и внизу, в
   **Artifacts**, скачать `TrueThrills-Android-apk`. Внутри
   `TrueThrills-Android-0.9.2.apk`.
4. Перекинуть на телефон и установить поверх прежнего. Подпись та же, номер
   версии тот же — Android поставит как обновление, удалять приложение не надо,
   и места чтения с закладками не потеряются.

Имя файла от сборки к сборке не меняется, пока не менялся `versionName` в
`android/app/build.gradle`. Поэтому старый и новый APK на вид одинаковы —
ориентироваться по дате скачивания.

Помощнику в чате этот шаг недоступен: он не запускает ни Actions, ни сборку.
Его дело — сказать прямо, что правка нативная и APK придётся пересобрать.

## 6. Что должен уметь проверять помощник, даже не запуская код

Прогоны запускает не он, но он обязан знать, что они есть, и просить владельца
их запускать, если тот работает с исходниками на компьютере:

```bash
npm run lint          # разбор кода
npx tsc --noEmit      # проверка типов
npm test              # сборка и около тридцати наборов проверок
npm run test:design   # снимки экранов и проверки по настоящим пикселям
```

`npm run test:design` — самый ценный для читалки: он снимает экраны в
`outputs/ui/` и разбирает настоящие пиксели. Оборот страницы рисует шейдер, и о
нём нельзя спросить разметку — только посмотреть, что вышло на экране.

## 7. Где мы остановились

Последняя большая работа — **читалка и переворот страницы**. Коротко, чтобы
помощник не начинал с нуля:

- Разбивка текста на строки и страницы своя, не браузерная: `lib/page-text.ts`.
  Один и тот же разбор кормит и настоящий текст на экране, и картинку для
  оборота.
- Переворот страницы: `lib/page-curl.ts`. Лист — настоящая поверхность, сетка из
  112 столбцов на профиле бумаги, с перспективной проекцией. Строки на листе
  гнутся вместе с бумагой — так и в Google Play Книгах.
- Профиль листа: наклон идёт по сглаженной ступеньке, у корешка и у свободного
  края бумага плоская, гнётся середина. Это арка, а не завиток.
- Сама читалка: `components/studio/story-reader.tsx`, стили —
  `components/studio/story-reader.css`.
- Без WebGL бумага не гнётся: уходящая страница съезжает и тает. Подделывать
  изгиб там, где его нечем нарисовать, хуже, чем показать простое движение.
- Оборот переживает смену настроек читалки. Раньше при смене фона холст
  создавался заново, старый контекст WebGL терялся, и оборот умирал до конца
  сеанса — это и была «анимация рушится». Теперь контекст создаётся один раз, а
  цвет бумаги передаётся ему отдельно (`Curl.paper()`). Пересоздавать холст
  нельзя — это главный подводный камень этого файла.
- Снимок страницы помнит, при каких настройках он снят: размер, засечки, фон,
  ширина полосы. Иначе на первом кадре оборота показывался снимок от прежних
  настроек.
- Тумблер «как на устройстве» в настройках читалки: дорожка вытянутая, отклик в
  руку сильный (`haptic('heavy')`). Сила отклика идёт через мост в приложение,
  значит **нужен новый APK** — см. Шаг 5 выше.

**Что осталось непроверенным:** скорость оборота на настоящем телефоне. В
проверочной среде рисует программный драйвер, это не показатель.

**Открытые задачи, отложенные ранее:** витрина канала для ПК; адрес для связи в
политике приватности; реестр прав на медиафайлы; четыре предупреждения
`drizzle-kit`, которые касаются только разработки; учебное восстановление из
резервной копии на другой машине.
