# True Thrills 0.9.2 — шесть экранов с утверждённого листа

Ветка `design/six-screens`, основана на `8da3db0`. Одиннадцать коммитов,
`5bc6112` … `dac1ff9`. Android versionCode 22, versionName 0.9.2.
Windows-студия версии не меняла: её нативный код не трогали.

## Что сделано

**Оформление.** Шесть экранов с листа `REFERENCE-APPROVED.png`: главная S01,
фотоплеер S02, редакционная шапка подкастов S03, типографический плеер S04,
экран эфира S05, запись эфира S06. Тема перенесена на видео, истории,
настройки, читалку и студию. Три роли шрифтов: Manrope в интерфейсе, Lora в
редакционных заголовках, Roboto Condensed в узких. Все четыре языка покрыты,
включая ș/ț и кириллицу.

Фон приложения переведён с `#101113` (значение из текста спецификации) на
`#121619` — тон, измеренный на самом листе. На нём фотографии сидят в экране,
а не висят поверх мёртво-серого.

**Новые функции сервера.**

- *Форма звука.* Пики считает воркер эфира вне запроса: по одному файлу за
  проход и только когда эфир не занимает процесс. Ограничены размер файла
  (400 МБ), время анализа (120 с) и объём в памяти. Кэш в таблице
  `audio_peaks`, ключ — ключ файла, к нему записывается sha256. Старые выпуски
  заполняются тем же проходом. Строки без файла убирает `prune-orphans`.
  Пока пиков нет, `/api/peaks` отвечает `pending`, а плеер показывает
  спокойное состояние и работающую полосу перемотки.
- *«Далее».* Следующий опубликованный аудиовыпуск по отображаемому порядку
  раздела. Черновики, видео и выпуски без файла пропускаются, на последнем
  блок исчезает. Автоматического перехода по окончании нет.
- *Фильтр записей эфира* в каталоге подкастов; карточка «Архив эфиров» на
  экране эфира открывает его.

**Native.** Системная кнопка «Назад» закрывает меню плеера, затем сворачивает
плеер, затем закрывает листы, затем возвращает на главную и только потом
отдаётся системе. До этого WebView знал лишь про историю страницы, и из
развёрнутого плеера Back выбрасывал из приложения; с полноэкранным плеером
это стало заметнее. Требуется новая сборка APK.

## Миграция

`drizzle/0009_first_dormammu.sql` — таблица `audio_peaks`. Применяется
`update-safe.sh` вместе с обновлением. Откат: таблица не используется старым
кодом, удалять её при откате не требуется.

## Что проверено автоматически

`npx tsc --noEmit`, `npm run lint`, `npm run build`, шестнадцать наборов из
`tests/`, включая `live-archive-integration` на настоящем FFmpeg — он доводит
пики до готовности и проверяет, что снятая с публикации запись прячет и форму
звука. `design-preview` снимает все экраны на production-сборке и проводит
системный Back через меню, плеер и раздел в настоящем браузере.

Сборка APK на этой ветке запускалась вручную (`workflow_dispatch`, run 29,
`dac1ff9`) и прошла: подписанный `0.9.2` лежит артефактом. Ветка
`design/six-screens` не входит в список веток автосборки — при следующих
правках нативного кода запускать вручную, иначе Java никем не компилируется.

`browser-integration` в песочнице без Google Chrome падает на шаге эфира
из-за отсутствия AAC — это не сигнал о коде; в CI он проходит.

## Что не проверено и требует живого устройства

- Пауза, переживающая сворачивание приложения.
- Эфир с заблокированным экраном и уведомление MediaStyle.
- Пуш на заблокированном телефоне, все четыре языка.
- Системный Back на самом телефоне: в браузере проверена вся цепочка, но
  нативный вызов `evaluateJavascript` проверяется только на устройстве.
- Донат с настоящими URL Boosty и PayPal.
- Форма звука на длинных реальных выпусках: сколько занимает проход воркера
  на VPS и не мешает ли он эфиру.

## Порядок выкладки

1. Снять и проверить backup (`scripts/backup-data.mjs`, затем
   `scripts/verify-backup.mjs`).
2. Убедиться, что активного эфира нет.
3. Обновить сервер `scripts/update-safe.sh` — он применит миграцию `0009`.
4. Дождаться, пока воркер посчитает пики для существующих выпусков; следить
   по журналу событий `peaks-ready` и `peaks-failed`.
5. Собрать и установить APK 0.9.2, пройти список живых проверок выше.

Публикацию не выполнять автоматически: решение принимает владелец.
