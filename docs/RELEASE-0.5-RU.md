## Что изменено

- Режим **«Звук из FL Studio»**, сохранение источника, канала, усиления и фильтра на этом устройстве. Стереосигнал идёт через оба канала в запись и WebRTC; каждый канал участвует в измерении уровня. Моно-входы 1/2 остаются доступны.
- Явное сообщение о необходимости HTTPS при заблокированном микрофоне. Защиту браузера приложение не обходит.
- Web Push о начале эфира, новых подкастах и историях. Регистрация слушателя не нужна: управление подпиской защищено отдельным случайным токеном устройства, в базе хранится его хеш.
- Выбор категорий, отключение, проверка доставки, переход из уведомления в нужный выпуск/эфир. Если браузер запретит автовоспроизведение после перехода, остаётся кнопка «Включить звук».
- Очередь в SQLite; отдельный обработчик внутри Node.js запускается через instrumentation и работает каждые 5 секунд даже без открытой страницы. Миграция добавляет только три новые таблицы и индекс.
- Исправлена конкретная причина обрыва фонового эфира: подтверждённое студией WebRTC-соединение не удаляется лишь из-за того, что Android приостановил таймеры страницы слушателя.
- Повторный `vps-setup.sh` сохраняет существующий nginx-конфиг и будущие настройки HTTPS, не затирает изменённые tracked-файлы, обновляет код только fast-forward, устанавливает devDependencies для сборки. Next.js запускается на `127.0.0.1:3000`.
- Скрипт `enable-https.sh` для подключения домена, Certbot, сохранения исходного nginx-конфига и записи PUBLIC_SITE_URL.
- Пример `.env.example`, технический контекст проекта и скрипт резервного копирования SQLite через online backup API.

## Что сделать после появления домена

1. Добавить DNS A-запись домена на `129.152.8.230`.
2. После получения этих изменений обновить сервер привычным скриптом `vps-setup.sh`. До публикации изменений в GitHub повторный запуск скачает прежний код — проверяй коммит.
3. В каталоге `/opt/truethrills` выполнить `sudo bash scripts/enable-https.sh example.com`, заменив `example.com` своим доменом. Ответить на вопросы Certbot. Скрипт устанавливает `PUBLIC_SITE_URL=https://example.com` в серверном `.env` и перезапускает приложение. Сертификат/сервис на реальном VPS здесь не проверены.
4. Открыть HTTPS-адрес, войти автором и проверить запись. Затем настроить уведомления на телефоне. На прежнем HTTP-адресе микрофон и push не заработают.
5. Передать фактический домен для обновления URL в Windows/Android и пересборки оболочек с прежним Android signing key. Сейчас они всё ещё направлены на прежний сайт; установщики в этой работе не пересобирались.

## Уведомления и блокировка Android

В HTTPS-версии открой **Настройки → Уведомления на этом устройстве**, выбери события, нажми **Включить уведомления** и разреши запрос на показ уведомлений. **Проверить доставку** отправляет реальное тестовое уведомление; положительный ответ означает принятие сервисом, а не доказанный показ на телефоне.

Два независимых канала с одним и тем же интерфейсом (`hooks/use-notifications.ts` сам определяет, какой использовать):

- **Браузер/десктоп** — обычный Web Push через Chrome/Firefox с VAPID-ключом (как раньше). Ключ хранится в SQLite, в исходники не включён.
- **Android APK** — нативный Firebase Cloud Messaging. Встроенный WebView не поддерживает `PushManager`, поэтому нативный код (`android/app/src/main/java/com/truethrills/listener/MainActivity.java`, `PushService.java`, `PushClient.java`) получает токен через `FirebaseMessaging`, регистрирует его на сервере тем же `/api/notifications`, и сам строит системное уведомление в `PushService.onMessageReceived` — работает и при закрытом приложении. Мост `AndroidPush` в WebView прокидывает те же действия (включить/выключить/категории/проверка) в тот же экран настроек, без отдельного UI.

Обе подписки хранятся в одной таблице `push_subscriptions` (колонка `kind`: `webpush`/`fcm`) и используют общую очередь `push_outbox` — публикация одного события рассылается сразу в оба канала.

**Настройка сервера для нативного Android push:**
1. В консоли Firebase (проект уже создан — `true-thrills`) открой Настройки проекта → Сервисные аккаунты → «Создать закрытый ключ», скачай JSON.
2. Загрузи файл на VPS в `/opt/truethrills/firebase-service-account.json` (`chmod 600`, владелец — тот же пользователь, что запускает сервис).
3. Добавь в `.env` сервера: `FIREBASE_SERVICE_ACCOUNT_FILE=/opt/truethrills/firebase-service-account.json`, перезапусти `truethrills.service`.

**Настройка пересборки APK:** в GitHub Actions → Secrets репозитория добавь `GOOGLE_SERVICES_JSON_BASE64` (содержимое `google-services.json`, полученного при регистрации Android-приложения в Firebase, в base64: `base64 -w0 google-services.json`) — рядом с уже существующими `ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD`. Сборка теперь идёт через Gradle (не через прежний `android/build.py`, который не умеет тянуть Maven-зависимости Firebase).

Нужны разрешения на показ уведомлений (Android 13+ запрашивает их при первом запуске) и показ на экране блокировки. Принудительная остановка приложения, «Не беспокоить», экономия батареи и отсутствие Google Play Services на устройстве могут влиять на показ и время доставки.

Пилот: 100 подписанных устройств (общий лимит на оба канала). Публикация уведомляет один раз при первом опубликовании; правки/повторное опубликование не создают дубликат. Черновики не рассылаются. Срок доставки начала эфира — 120 секунд с высоким приоритетом; публикаций — 24 часа. До 5 попыток при временной ошибке; истёкшие подписки удаляются.

**Фоновое воспроизведение живого звука во время эфира — отдельная, ещё не решённая задача.** Push-уведомления (в том числе нативные FCM) сообщают о начале эфира даже при закрытом приложении, но сам приём звука внутри активного прослушивания по-прежнему идёт через WebView/браузер без нативного Android MediaSessionService. Для проверки: запустить эфир, заблокировать телефон на 15–30 минут во время прослушивания, проверить звук, затем повторить с подкастом и переходом между Wi-Fi/мобильной сетью. Физический Android здесь не подключён, эта проверка не выполнена. Отдельно не проверено на реальном телефоне: получение FCM-токена, показ уведомления при закрытом приложении, переход по нему в нужный экран.

## Резервное копирование

Из каталога приложения: `node --env-file=.env scripts/backup-data.mjs /absolute/private/backups`.

Не публикуй и не удаляй выпуски во время резервного копирования: SQLite копируется согласованно, но аудиокаталог — отдельно. Затем скопируй получившуюся папку на свой ПК; резервная копия на том же VPS не защищает от потери сервера. `.env` с паролями сохраняется отдельно и приватно. База также содержит секреты push-подписок — не публикуй её.

## Проверки

Локально: TypeScript, производственная сборка Next.js, серверные регрессии Node/SQLite/аудиофайлы. Новые тесты проверяют анонимную push-подписку, владение токеном устройства, шифрование с независимой расшифровкой RFC 8291, категории, отсутствие дубликатов, повторы, удаление истёкших подписок, сохранение фонового peer. Тесты используют имитацию push-сервиса и не отправляют уведомления настоящим слушателям. Звуковые тесты проверяют отдельные стереоканалы и параметры Opus; это не аппаратный тест интерфейса.

`node tests/api-integration.mjs` (включает нативный FCM-путь: подписка, рассылка через подписанный JWT сервисного аккаунта с проверкой подписи, удаление истёкшего токена — сервис Google не вызывается, только `fetch` подменён), `node tests/studio-audio.mjs`, `node tests/device-discovery.mjs`, `node_modules/.bin/tsc --noEmit`, `npm run build`, `bash -n scripts/vps-setup.sh scripts/enable-https.sh`. Android/Gradle-сборка проверяется только в GitHub Actions — здесь нет сети до `dl.google.com`.
