# Поверхности True Thrills: кто какой экран получает

Один и тот же сайт обслуживает пять разных «поверхностей». Здесь записан
договор: какая поверхность какой каркас получает и по какому признаку.
Договор держит проверка `tests/browser/surfaces.mjs`. Если правишь код
определения поверхности, сначала правь эту таблицу, потом код, потом
проверку.

## Таблица

| Поверхность | Признак | Каркас (`.app-shell`) | Навигация | «Скачать приложение» |
|---|---|---|---|---|
| Слушатель на телефоне | экран меньше 1024 px | `is-listener` (на главной ещё `is-immersive`) | нижняя панель | есть, если не внутри APK |
| Слушатель на сенсорном планшете | касание без мыши; планшет масштабируется как телефон (`TABLET_AS_PHONE` в `app/layout.tsx`) | `is-listener` | нижняя панель | есть |
| Слушатель на ПК в браузере | ширина от 1024 px **и** мышь (`hover: hover`) | `is-desk`: сайт «Студия звука» | боковое меню `.desk-rail` слева, плеер полосой снизу | есть, в боковом меню |
| Слушатель в программе для ПК (без входа) | как выше, плюс `window.chrome.webview` | `is-desk` | боковое меню | **нет**: человек уже в программе |
| Автор на ПК (браузер или программа) | вход владельца, ширина от 1024 px и мышь | `is-author` | боковая панель студии; в программе ещё меню программы `.shell-menu` | нет |
| Автор с телефона | вход владельца, экран меньше 1024 px | `is-author` | нижняя панель | нет |
| Приложение Android | `window.TrueThrillsNative` | как телефон | нижняя панель | нет; звук играет родной плеер Media3 |

## Где это в коде

- `hooks/use-wide-screen.ts` — `WIDE_SCREEN_QUERY = '(min-width: 1024px) and (hover: hover)'`.
- `hooks/use-desktop-app.ts` — программа для ПК (WebView2).
- `lib/native-client.ts` — `hasNativeClient()`: приложение Android.
- `app/studio.tsx`:
  - `author = isOwner && !audience` — автор, если не включён «вид слушателя»;
  - `wide = wideScreen && author` — студия на ПК;
  - `desk = wideScreen && !author` — сайт для ПК, только слушателю;
  - класс каркаса: `author ? 'is-author' : desk ? 'is-desk' : 'is-listener'`.
- `components/studio/desk.css` — все правила ПК-слушателя. Каждое правило
  начинается с `.is-desk` или с класса `desk-*`, поэтому телефон и студию они не задевают.
- `components/studio/desk-rail.tsx`, `desk-home.tsx` — меню и полки ПК.

## Правила разграничения

1. Каркас ПК (`.desk-rail`, `desk-*`) получает только слушатель с мышью и
   экраном от 1024 px. В странице автора бокового меню слушателя нет совсем:
   ни видимого, ни скрытого стилем.
2. Студия получает только владелец. «Вид слушателя» в студии показывает
   каркас слушателя для того же экрана.
3. Внутри программы для ПК не предлагается скачать приложение.
4. Окна поверх каркаса ПК закрываются по Escape:
   - читалка сначала закрывает открытую панель, потом себя;
   - видео: при открытии фокус остаётся на окне, а не внутри плеера YouTube, иначе Escape уходит в YouTube;
   - окно поддержки.

   Все три окна лежат над боковым меню.
5. На всех поверхностях и во всех разделах (главная, аудио, видео,
   истории, эфир, настройки):
   - нет прокрутки вбок;
   - кнопки карточки выпуска не выходят за её край;
   - на странице нет ошибок.
6. Телефонная раскладка закреплена в `tests/fixtures/layout-lock.json`.
   Работа над ПК не должна её двигать (см. `CLAUDE.md`).

## Что нашла проверка при введении (октябрь 2026)

- Читалка не закрывалась по Escape на ПК.
- Окно видео не закрывалось по Escape: фокус уходил внутрь плеера YouTube.
- В каталоге на ПК (1024 и 1440 px) кнопка «Поделиться» вылезала за карточку.
- У автора с телефона кнопки «Закрепить» и «Удалить» уходили за край экрана.

Все четыре исправлены. Каждое исправление проверено мутацией: без него
проверка падает и называет поломку словами.
